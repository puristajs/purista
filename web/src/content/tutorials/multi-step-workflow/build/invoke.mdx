Publish the workflow and keep the two stage agents private. Define one business
authorization function and use it at both public boundaries. The command guard
protects the command's own address. The mounted target guard protects callers
that invoke the workflow address directly.

```ts title="src/service/support/v1/requireSupportCaseResolution.ts"
export async function requireSupportCaseResolution(
	policy: SupportCasePolicy,
	input: { tenantId?: string; principalId?: string; caseId: string },
) {
	if (!input.tenantId || !input.principalId) {
		throw new HandledError(StatusCode.Unauthorized, 'A valid session is required')
	}
	if (!(await policy.canResolve({
		tenantId: input.tenantId,
		principalId: input.principalId,
		caseId: input.caseId,
	}))) {
		throw new HandledError(StatusCode.Forbidden, 'Support case resolution is not allowed')
	}
}
```

```ts title="src/service/support/v1/harness/supportHarnessMount.ts"
export const supportHarnessPolicy = {
	publish: { agents: [], workflows: ['resolve_support_case'] },
	targets: {
		agents: {},
		workflows: {
			resolve_support_case: {
				beforeGuards: {
					caseAccess: async (context, input) => {
						await requireSupportCaseResolution(context.resources.supportCasePolicy, {
							...context.identity,
							caseId: input.caseId,
						})
					},
				},
			},
		},
	},
} as const
```

Create stable session and run ids from the trusted tenant, principal, and case
identity. Hashing keeps raw identity values out of infrastructure identifiers
while preventing one caller from sharing a durable run with another.

```ts title="src/service/support/v1/durableIdentity.ts"
export function durableResolutionIdentity(tenantId: string, principalId: string, caseId: string) {
	const digest = createHash('sha256').update(`${tenantId}:${principalId}:${caseId}:support-resolution-v1`).digest('hex')
	return {
		sessionId: `support-resolution:${digest}`,
		runId: `support-resolution-run:${digest}`,
	}
}
```

Declare the workflow address and add the command guard before writing command
logic. Authentication middleware belongs to the Hono chapter. This guard makes
the business decision: may this authenticated caller resolve this case?

```ts title="src/service/support/v1/command/resolveSupportCase/resolveSupportCaseCommandBuilder.ts"
export const resolveSupportCaseCommandBuilder = supportV1ServiceBuilder
	.getCommandBuilder('resolveSupportCase', 'Run a durable multi-step support resolution')
	.addPayloadSchema(supportResolutionInputSchema)
	.addOutputSchema(supportResolutionOutputSchema)
	.canInvokeWorkflow(
		'Support',
		'1',
		'resolve_support_case',
		supportResolutionHarness.contracts.workflows.resolve_support_case,
	)
	.setBeforeGuardHooks({
		caseAccess: async function (context, payload) {
			await requireSupportCaseResolution(context.resources.supportCasePolicy, {
				tenantId: context.message.tenantId,
				principalId: context.message.principalId,
				caseId: payload.caseId,
			})
		},
	})
```

Invoke the workflow with both durable identifiers. A repeated command with the
same tenant, principal, case, and input resumes the same run. Harness rejects
changed input bound to that run id. The workflow target guard runs again because
the workflow is independently addressable and must remain safe for every caller.

```ts title="src/service/support/v1/command/resolveSupportCase/resolveSupportCaseCommandBuilder.ts"
.setCommandFunction(async function (context, payload) {
	const tenantId = context.message.tenantId
	const principalId = context.message.principalId
	if (!tenantId || !principalId) throw new HandledError(StatusCode.Unauthorized, 'A valid session is required')
	const identity = durableResolutionIdentity(tenantId, principalId, payload.caseId)
	const outcome = await context.workflow.Support['1'].resolve_support_case.run(payload, {
		sessionId: identity.sessionId,
		durable: { runId: identity.runId },
	})
	if (outcome.status !== 'completed') throw new Error('Support resolution did not complete')
	return outcome.output
})
```

Accept models and storage as composition inputs so tests can inject strict fake
providers while the live process can inject real adapters.

```ts title="src/createSupportService.ts"
export function createSupportService(eventBridge: EventBridge, logger: Logger, options: Readonly<{
	supportCasePolicy: SupportCasePolicy
	storage: HarnessStorage
	sandbox?: Sandbox
	workspace?: DurableWorkspace
	classificationModel: { provider: ModelProvider; model: string }
	resolutionModel: { provider: ModelProvider; model: string }
}>) {
	return supportV1Service.getInstance(eventBridge, {
		logger,
		resources: { supportCasePolicy: options.supportCasePolicy },
		ai: {
			storage: options.storage,
			...(options.sandbox ? { sandbox: options.sandbox } : {}),
			...(options.workspace ? { workspace: options.workspace } : {}),
			models: {
				classification_model: options.classificationModel,
				resolution_model: options.resolutionModel,
			},
			telemetry: { contentCaptureMode: 'NO_CONTENT' },
		},
	})
}
```

The optional live entry point uses `localDurableExecution` under `.data`. The
bundle supplies SQLite run storage plus a matching durable workspace and local
files-only sandbox. All three boundaries must agree when a session resumes in a
new process. The mounted Harness owns their shutdown through the Support
service.
