Wrap each recoverable stage in `context.step`. Under a durable invocation,
Harness commits the JSON-serializable output after the function succeeds. On a
later attempt of the same run, a committed step returns its stored output
without executing the function again.

```ts title="src/harness/support/supportResolutionWorkflow.ts"
const classification = supportClassificationSchema.parse(
	await context.step(
		'classify-case-v1',
		() => context.agents.classify_support_case(context.input),
	),
)
```

Give stable step ids version suffixes. Changing the meaning of a deployed step
while old runs can resume is unsafe; add a new id when its contract changes.

Add a bounded retry policy to the planning stage.

```ts title="src/harness/support/supportResolutionWorkflow.ts"
const plan = resolutionPlanSchema.parse(
	await context.step(
		'plan-resolution-v1',
		() => context.agents.plan_support_resolution({ ...context.input, classification }),
		{
			retry: {
				maxAttempts: 2,
				minDelayMs: 100,
				maxDelayMs: 1_000,
				backoff: 'exponential',
				shouldRetry: (error) => isHarnessError(error) && error.retriable,
			},
		},
	),
)

return { caseId: context.input.caseId, classification, plan }
```

The retained source uses a short exponential backoff so the example behaves
like production while remaining practical to test. `shouldRetry` accepts only
an exported Harness error whose `retriable` flag is true. Validation,
authorization, cancellation, and unknown programming errors therefore fail
immediately instead of being repeated.

Every agent attempt, including a retry, consumes one
`maxChildAgentCalls` slot. Set the budget from the maximum intended path rather
than only counting logical steps.

`context.step` is a pass-through during a non-durable invocation. Supply a
durable run option and durable storage when checkpoint recovery matters.
