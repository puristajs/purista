Create a clean project and install the complete published manifest.

```bash title="Create and enter the multi-step workflow project" replay="parent"
npm create purista@2.2.0 multi-step-support-workflow -- --runtime node --event-bridge default --non-interactive --defaults
cd multi-step-support-workflow
```

```bash title="Install the multi-step workflow dependencies" replay="project"
npm install
```

Generate the service, two specialist agents, owning workflow, and application
command through the PURISTA CLI.

```bash title="Generate workflow definitions and command" replay="project"
npm run add:service -- support --description "Own support case resolution" --non-interactive
npm run add:agent -- classify-support-case --service support --service-version 1 --description "Classify one support case" --non-interactive
npm run add:agent -- plan-support-resolution --service support --service-version 1 --description "Plan one support resolution" --non-interactive
npm run add:workflow -- resolve-support-case --service support --service-version 1 --description "Run recoverable support resolution stages" --non-interactive
npm run add:command -- resolve-support-case --service support --service-version 1 --description "Run a durable multi-step support resolution" --non-interactive
```

The CLI creates one module and colocated test for each agent and workflow. Keep
those boundaries. The next page fills the generated files, adds shared schemas,
and composes the modules in a small service Harness definition.
