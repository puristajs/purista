This chapter teaches how to build recoverable multi-step AI work. You create a
fresh PURISTA project, generate the service, agents, workflow, and command with
the CLI, then fill in each generated boundary. A classification stage runs
first. A planning stage consumes the validated classification. Each stage has
a named durable checkpoint, so a later invocation can resume without repeating
completed model work.

The Example Bank workflow resolves one support case, but the focus is the
Harness and PURISTA execution model:

- schema-validated output becomes the next stage input;
- `context.step` creates explicit durable checkpoint boundaries;
- step retry is bounded and counts against the child-agent call budget;
- stable tenant, principal, and case identity makes a repeated command resume
  the same work;
- SQLite persists live checkpoints across process restarts;
- both the command and directly addressable workflow enforce business access;
- the workflow remains addressable through EventBridge.
