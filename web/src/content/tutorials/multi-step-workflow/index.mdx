Some jobs must happen in a fixed order. In this chapter, one agent classifies a support case. A second agent uses that classification to plan the next action.

A durable Harness workflow coordinates both stages. It stores each completed step, retries only temporary planning failures, and can reuse its checkpoints after a process restart.

You will learn how to:

- give each agent one typed stage and one named model;
- call child agents in sequence with stable call IDs;
- create durable steps with stable step IDs;
- bound retries and distinguish retryable failures from permanent failures;
- derive stable, caller-scoped session and run IDs;
- protect both the PURISTA wrapper command and mounted workflow; and
- verify checkpoint reuse with strict fake providers and local durable storage.

The support case is deliberately small. The workflow behavior remains the focus, and every default test runs without credentials.
