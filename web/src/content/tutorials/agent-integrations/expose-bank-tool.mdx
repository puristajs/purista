---
title: Declare one guarded command tool
description: Add one typed, read-only PURISTA command tool to the generated agent.
order: 151
status: published
---

Open the generated agent builder. Add payload and output schemas first, then
declare the one command it may invoke. `canInvoke` names a real PURISTA command;
it does not copy the handler or bypass its business guard.

```ts title="classifyCustomerSupport agent builder"
.canInvoke('banking', '1', 'listTransactions', {
  outputSchema: accountStatementSchema,
  payloadSchema: z.undefined(),
  parameterSchema: z.object({ accountId: accountIdSchema }),
})
.useBuiltInTools(false)
```

In the run function, never take the account from a model tool call. Use the
already validated request payload:

```ts title="Call only after the typed routing decision"
const statement = routing.status === 'eligible-for-application-routing'
  ? await context.invoke.tools['banking.1.listTransactions'].call(undefined, {
      accountId: context.payload.accountId,
    })
  : undefined
```

The target command repeats the normal account guard with the original PURISTA
principal and tenant. This protects the service even if a future agent change
is incorrect.
