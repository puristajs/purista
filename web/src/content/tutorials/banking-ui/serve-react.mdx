The visible result is a small React application built with Vite. Hono serves
the finished files from `examples/banking/ui/dist`; it does not run a separate
frontend server in production mode:

```ts title="examples/banking/src/index.ts"
hono.app.get('/assets/*', serveStatic({ root: tutorialUiDirectory }))
hono.app.get('/', serveStatic({ root: tutorialUiDirectory, path: 'index.html' }))
```

`npm run dev -w @purista/banking-tutorials` starts the Node server. Build the
UI separately with `npm run build:ui -w @purista/banking-tutorials` whenever
you change a React source file. The checked-in UI uses the default
shadcn-compatible tokens in `ui/src/styles.css`; shadcn components are source
files, so no component library needs to run at request time.

The UI already makes real requests to the local protected API. Before showing
account data, it posts the chosen synthetic tutorial person to `/auth/login`.
The server stores that fixture identity in an in-memory session and returns an
opaque HttpOnly cookie. The browser sends the cookie on later API requests. The
fixture is useful for learning, but it does not verify a real person's
credential or provide a production identity provider.

## Test the response

Use either the browser or this request:

```bash title="Inspect the served document"
curl --fail http://127.0.0.1:3010/
```

The response must contain the heading `Example Bank`. If it is not present,
check that you started `@purista/banking-tutorials`, rather than another local
server on the same port.
