This chapter teaches persistent conversation sessions in a standalone PURISTA
project. The small `Support` service keeps the example concrete, but the
capability applies to any agent that must understand earlier turns.

You will keep three storage responsibilities separate:

- **Harness storage** owns agent sessions, transcript messages, run receipts,
  durable checkpoints, and external waits.
- **Harness memory** stores facts that an agent or tool writes explicitly. It
  does not automatically contain the transcript.
- **PURISTA StateStore** remains application state for values such as login
  sessions. It is not a database for AI conversation history.

By the end, one identity-scoped conversation survives process restarts, retains
only complete bounded turns, and can be exported or cleared through
business-authorized PURISTA commands.
