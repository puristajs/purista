title: Install the Hono HTTP packages
description: Add the PURISTA Hono integration and Node HTTP adapter to the generated project.
order: 8
---

The project has a bridge and a placeholder service, but nothing accepts HTTP
requests. Add that transport without putting banking logic inside HTTP routes.

Run this in `example-bank`:

```bash title="Install the HTTP integration and its Node listener"
npm install --save-exact @purista/hono-http-server@3.2.4 @hono/node-server@2.1.0
```

The packages do different jobs:

| Package | Job in this application |
| --- | --- |
| `@purista/hono-http-server` | Map exposed PURISTA command definitions to Hono HTTP routes. |
| `@hono/node-server` | Open a Node HTTP socket and forward requests to Hono's request handler. |

The PURISTA integration depends on Hono itself. Our source imports the
integration and Node adapter, so these are the two direct dependencies to
declare. Installation does not create configuration, start a server, or
expose a command.

Check that both appear under `dependencies` in `package.json`. The running
application needs them, not only the development tools.

```bash title="Check the installed HTTP packages"
npm ls @purista/core @purista/hono-http-server @hono/node-server
```

Expect core and the Hono integration at `3.2.4`, and the Node adapter at
`2.1.0`. npm may show repeated dependencies as `deduped`; that means it
reuses an installed copy.

No Docker container is needed: Node opens the listening socket and the default
bridge stays in memory. Next, [write the server configuration](/tutorials/start-a-purista-project/configure-hono/).
