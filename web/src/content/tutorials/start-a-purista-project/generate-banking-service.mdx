We have a working HTTP listener. Now create the service that will own the
bank's operations. A service groups related behavior and gives its contracts a
name and version.

Stop the development server if it is running. In `example-bank`, run:

```bash title="Generate version 1 of Banking"
npm run add:service -- banking \
  --description "Manage synthetic banking transactions" --non-interactive
```

The default naming convention produces the directory `src/service/banking`.
Use this lowercase `banking` key in later CLI commands. The generated metadata
uses `Banking` as the runtime service name. Version `1` is the default.

The generator creates these files:

| Path below `src/service/banking/` | Purpose |
| --- | --- |
| `generalBankingServiceInfo.ts` | The runtime name and description shared by versions. |
| `v1/bankingServiceConfig.ts` | The schema for this version's configuration. |
| `v1/bankingV1ServiceBuilder.ts` | The builder from which we create banking operations. |
| `v1/bankingV1Service.ts` | Collect this version's operation definitions. |
| `v1/bankingV1Service.test.ts` | Check that the service configuration is valid. |

Leave these files unchanged for now. Versioning lets a future version coexist
with version 1 instead of silently changing its contract.

## Add the service to startup

Generating files does not start the service. Replace `src/index.ts` with:

```ts title="src/index.ts"
import { gracefulShutdown, initLogger } from '@purista/core'
import { getEventBridge } from './eventbridge.js'
import { startHttpServer } from './http.js'
import { bankingV1Service } from './service/banking/v1/bankingV1Service.js'

async function main() {
	const logger = initLogger()
	const eventBridge = await getEventBridge(logger)
	const banking = await bankingV1Service.getInstance(eventBridge, { logger })
	await banking.start()

	const { honoService, closeSocket } = await startHttpServer({
		eventBridge,
		logger,
		services: [banking],
	})

	gracefulShutdown(logger, [honoService.prepareDestroy(), eventBridge, banking, closeSocket, honoService])
	logger.info('Example Bank is listening on http://127.0.0.1:3000')
}

main().catch(error => {
	process.stderr.write(`${error}\n`)
	process.exit(1)
})
```

Compared with the preceding page, we changed the import, created and started a
Banking instance instead of Ping, passed it to HTTP registration, and included
it in shutdown. The Ping files can remain on disk; they are no longer part of
the running application.

```bash title="Check and start the new service"
npm test
npm run dev
```

The tests now include the Banking setup test. Look for the startup log
`service Banking 1 started`. In a second terminal, `curl -i
http://127.0.0.1:3000/health` must still return `200`.

The service has no banking command yet, so `/api/v1/bank` still returns
`404`. That is the next change, not a server failure.
