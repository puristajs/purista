Open `src/index.ts`. The generated `main` function creates a logger, asks
`getEventBridge` for a started bridge, creates the Ping service, and starts it.
A **service definition** describes a service; a **service instance** is the
running object created from that definition with `getInstance(...)`.

Ping is a generated placeholder. Its command returns no useful data yet.
We will leave those files in place, but replace Ping with our Banking service
in the running application.

## Follow startup into the bridge

Open `src/eventbridge.ts`. It creates a `DefaultEventBridge`, calls
`start()`, and returns it. An **EventBridge** carries PURISTA messages between
services. This default implementation runs inside one Node process. It does
not install a broker, persist messages, or send them to another machine.

Keep this file unchanged. HTTP and banking must receive the same bridge
instance to communicate through this local bridge.

## Find the service files

| Generated path | What it owns |
| --- | --- |
| `src/index.ts` | Create instances, connect them, start them, and arrange shutdown. |
| `src/eventbridge.ts` | Choose and start the message transport. |
| `src/service/ping/generalPingServiceInfo.ts` | The service's name and description. |
| `src/service/ping/v1/pingV1ServiceBuilder.ts` | Configure version 1 of the service. |
| `src/service/ping/v1/pingV1Service.ts` | Collect its operation definitions. |
| `src/service/ping/v1/command/ping/schema.ts` | Describe accepted input and returned output. |
| `src/service/ping/v1/command/ping/pingCommandBuilder.ts` | Declare and implement the operation. |

The separate builder and composition files avoid a circular dependency:
commands import the builder, and the composition imports the commands.
A circular dependency would make each module require the other before it
could finish initializing.

## Find the generator scripts

Open `package.json` and look at `scripts`. For example,
`"add:service": "purista add service"` runs the project's installed CLI.
Inspect its options without generating anything:

```bash title="Inspect the project-local service generator"
npm run add:service -- --help
```

The first `--` tells npm to pass subsequent arguments to PURISTA. Later,
`npm run add:command -- get-bank-info ...` uses this same convention.
Use these local scripts so the project's CLI version and naming settings stay
consistent.
