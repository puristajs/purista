The generator writes a complete project, not a folder of disconnected code
samples. These are the files you will use first:

| File | Why it exists |
| --- | --- |
| `src/index.ts` | Composition root. It starts bridges and services, then starts the Node process. |
| `src/http.ts` | Hono HTTP composition created when you selected webserver support. |
| `src/eventbridge.ts` | Creates the selected EventBridge. |
| `src/service/ping/v1/` | A small generated service and command that prove the application can register a service. |
| `purista.json` | Generation settings, including naming and source-path conventions. |
| `package.json` | Project scripts and the project-local `@purista/cli` version. |

Open `package.json`. The important scripts are deliberately local to this
project:

```json title="package.json"
{
  "scripts": {
    "add:service": "purista add service",
    "add:command": "purista add command",
    "add:subscription": "purista add subscription",
    "add:stream": "purista add stream",
    "add:queue": "purista add queue",
    "add:queue-worker": "purista add queue-worker",
    "add:agent": "purista add agent"
  }
}
```

Use these scripts instead of installing a global CLI. They use the version
recorded in the project and follow the source layout in `purista.json`.

Run the generated tests once:

```bash title="Check the generated project"
npm test
```

This proves that the generated starting application type-checks and its starter
service tests run. It does not prove a banking workflow yet.
