This checkpoint adds an isolated worker to Example Bank. Alice can submit a
small synthetic CSV only for an account she may read. A PURISTA command guards
that business rule, then a queue worker writes the file into a private Docker
workspace, runs one reviewed `awk` calculation, and retains only a typed
summary in application state.

The Docker adapter is local-development infrastructure. It uses a digest-pinned
image, non-root user, no guest network, resource limits, and no host mounts,
Docker socket, credentials, or repository files. It is not a claim of a
multi-tenant production sandbox or durable workflow recovery.

## Generate the protected job boundary

Create the service, submit command, and queue worker before adding any Docker
configuration. PURISTA owns the request contract and business guard; the
sandbox is only a resource used by the worker.

```bash title="Generate the statement-analysis service and queue"
npm run add:service -- banking-statement-analysis \
  --description "Analyze synthetic statements in an isolated sandbox"
npm run add:command -- submit-statement-analysis \
  --service banking-statement-analysis --service-version 1 \
  --description "Queue one authorized synthetic CSV statement"
npm run add:queue -- analyze-statement \
  --service banking-statement-analysis --service-version 1 \
  --worker-name analyze-statement-in-sandbox --worker-mode continuous \
  --description "Analyze one statement in a private Docker sandbox"
```

Replace the generated payloads with the bounded CSV and job schemas, add the
account-read guard to the command and worker, and inject the sandbox resource
only in the application composition. The runnable implementation is
`examples/banking/src/sandbox/service.ts`.
