Start with the existing local application. Its commands, event subscriptions,
and queue workers share one process and use the tutorial's in-memory fixtures.
That baseline makes a transport change easier to diagnose: if a later profile
fails, first prove the business behaviour without a broker.

```bash
npm run dev -w @purista/banking-tutorials
npx vitest run examples/banking/src/banking.integration.test.ts
```

The server listens at `http://127.0.0.1:3010/`. Stop it with `Ctrl+C` when you
finish. A restart resets the default fixture state. It does not demonstrate
durable queues, cross-process delivery, or persisted transactions.
