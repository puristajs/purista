`examples/banking/src/distributed/dependencies.ts` is a small composition
helper. It returns an `eventBridge` and `queueBridge`; it does not modify any
service contract. A future composition root can select those instances without
teaching a command or queue worker about connection URLs.

```ts
export const createDistributedBankingDependencies = (environment = process.env) => ({
  eventBridge: new NatsBridge({
    servers: environment.BANKING_NATS_URL ?? 'nats://127.0.0.1:4222',
    topicPrefix: 'example-bank',
    durableSubscriptionMode: 'strict',
  }),
  queueBridge: new RedisQueueBridge({
    config: { url: environment.BANKING_REDIS_URL ?? 'redis://127.0.0.1:6379' },
    keyPrefix: 'example-bank:queue:',
  }),
})
```

This is server-side configuration, not caller-controlled request metadata.
Internal broker access still needs real service identities and broker access
controls when the profile is wired into a deployed environment. A tenant ID in
a message does not authenticate its sender.
