Example Bank begins as one local process with in-memory state. That is the
right place to learn commands, events, and queue workers. This checkpoint
prepares the external dependencies needed before moving work across process
boundaries: NATS JetStream for events and commands, Redis for queues, and
PostgreSQL for a later domain-persistence checkpoint.

It deliberately stops before a full distributed deployment. The application
does not yet select this factory at startup, start separate HTTP and worker
processes, write domain records to PostgreSQL, or prove restart recovery. A
running Compose stack alone is not proof that messages, jobs, or business
state survive a restart.

```mermaid title="The prepared dependencies have separate responsibilities"
flowchart LR
  App[Future PURISTA composition root] --> NATS[NATS JetStream\nevents and commands]
  App --> Redis[Redis\nqueue jobs]
  App --> Postgres[PostgreSQL\nfuture domain state]
```
