Run the focused banking suite from the PURISTA repository root:

```bash title="Run the local metrics scenario"
npm run test -w @purista/banking-tutorials
```

The test named `records bounded business metrics without account, person, or
transaction identifiers` signs in as Dana, records a high-value synthetic
transaction for `account-a`, then signs in as Bob and requests a statement for
the same account. Dana may record this fixture. Bob may read it, so these are
two separate business permissions.

The transaction makes the monitoring subscription write the
`example.bank.review.signals` counter. The statement command writes the
`example.bank.background.jobs` counter after its local queue accepts the
request. The test waits for that record before inspecting the in-memory
recorder.

There is no trace in this checkpoint. A trace links individual operations;
these counters deliberately aggregate many operations instead.
