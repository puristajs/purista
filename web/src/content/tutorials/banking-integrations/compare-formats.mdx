---
title: Compare the two formats
description: Keep the legacy wire contract separate from the banking transaction contract.
order: 41
---

Generate the command before writing its contract. This gives you a named,
tested service boundary instead of an unowned HTTP route.

```bash title="Generate the legacy import command"
npm run add:command -- import-legacy-transaction \
  --service banking --service-version 1 \
  --description "Normalize a documented legacy transaction"
```

The CLI creates `src/service/banking/v1/command/importLegacyTransaction/` and
wires its definition into the service. Keep its generated test: it proves the
command loads before you replace its starter contract.

The domain payload has no legacy names:

```ts title="The banking payload"
const transactionSchema = z.object({
  accountId: z.enum(['account-a', 'account-c']), sourceTransactionId: z.string().min(1),
  bookedAt: z.string().datetime(), amountMinor: z.number().int().positive(),
  currency: z.literal('EUR'), direction: z.enum(['debit', 'credit']),
})
```

Put the external wire schema beside the adapter, not in the domain command:

```ts title="src/legacy-bank.ts"
export const legacyBankTransactionSchema = z.object({
  source_id: z.string().min(1), account_ref: z.enum(['account-a', 'account-c']),
  booked_at: z.string().datetime(), amount: z.string().regex(/^\d+\.\d{2}$/),
  currency: z.literal('EUR'), dc: z.enum(['D', 'C']),
})
```

The two schemas make the change point clear: a new legacy field cannot silently
become part of every banking command.
