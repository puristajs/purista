---
title: Keep a business guard around the write
description: Check the caller's posting assignment after normalization and before recording a transaction.
order: 43
---

Authentication tells Hono who called. It does not decide whether that person
may post to an account. Add the same business guard used by the normal
transaction command to the generated import command.

```ts title="importLegacyTransaction command builder"
.canEmit(BankingTutorialEvent.transactionRecorded, transactionRecordedEventSchema)
.exposeAsHttpEndpoint('POST', 'legacy/transactions')
.setBeforeGuardHooks({
  postingAccess: async (context, payload) => {
    if (!context.resources.bankingRepository.canRecord(context.message.principalId, payload.accountId)) {
      throw new HandledError(StatusCode.Forbidden, 'You may not record transactions for this account')
    }
  },
})
.setCommandFunction(recordAndPublish)
```

The transform produces a domain `accountId`; the guard checks a business
assignment; only then does the handler write and emit an event. The reference
fixture gives Dana the `account-a` posting assignment and denies Bob.
