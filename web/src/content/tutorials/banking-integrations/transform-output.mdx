---
title: Export a statement safely
description: Generate a statement command and transform its already-authorized domain result into CSV.
order: 44
---

Create a second command for the export boundary.

```bash title="Generate the statement export command"
npm run add:command -- export-statement \
  --service banking --service-version 1 \
  --description "Export an authorized account statement as CSV"
```

The command returns the usual typed statement. Check the requested account in a
before guard. Check the returned result in an after guard, before CSV is
created. That makes an accidental cross-account repository result fail closed.

```ts title="Protect result scope before serialization"
.setAfterGuardHooks({
  statementScope: async (_context, result, _payload, parameter) => {
    if (result.accountId !== parameter.accountId || result.transactions.some(t => t.accountId !== parameter.accountId)) {
      throw new HandledError(StatusCode.Forbidden, 'The statement contains data outside the authorized account')
    }
  },
})
.setTransformOutput(z.string(), async (_context, result) => {
  const rows = result.transactions.map(t => [t.transactionId, t.bookedAt, t.amountMinor, t.currency, t.direction].join(','))
  return ['transactionId,bookedAt,amountMinor,currency,direction', ...rows].join('\n')
}, 'text/csv')
```

`setTransformOutput` changes only the HTTP representation. The command logic
still works with the typed banking statement.
