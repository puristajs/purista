A real integration often fetches a record from another server. Build that
boundary explicitly. Our mock will speak HTTP and return synthetic legacy
JSON; it will not call a real bank.

Create `src/mockLegacyBank.ts`:

```ts title="src/mockLegacyBank.ts"
import { createServer } from 'node:http'
import { pathToFileURL } from 'node:url'

/** A separate HTTP dependency with synthetic, tenant-scoped credentials and data. */
export function createLegacyBankMock() {
	const requests: { tenantId: string; principalId: string; accountId: string; sourceId: string }[] = []
	const server = createServer(async (request, response) => {
		const send = (status: number, body: unknown) => {
			response.writeHead(status, { 'content-type': 'application/json' })
			response.end(JSON.stringify(body))
		}
		const url = new URL(request.url ?? '/', 'http://mock.local')
		if (request.method !== 'GET') return send(405, { title: 'Use GET' })
		if (url.pathname === '/health') return send(200, { status: 'ok' })
		const tenantId =
			request.headers.authorization === 'Bearer mock-north'
				? 'tenant-north'
				: request.headers.authorization === 'Bearer mock-south'
					? 'tenant-south'
					: undefined
		if (!tenantId) return send(401, { title: 'Unknown mock credential' })
		const match = /^\/transactions\/([a-zA-Z0-9_-]+)$/.exec(url.pathname)
		if (!match) return send(404, { title: 'Unknown route' })
		const sourceId = match[1]
		const accountId = url.searchParams.get('accountId') ?? ''
		if (!['account-a', 'account-c'].includes(accountId)) return send(400, { title: 'Unknown fixture account' })
		if (tenantId === 'tenant-south' && accountId !== 'account-a') return send(403, { title: 'Account not assigned' })
		requests.push({ tenantId, principalId: String(request.headers['x-example-principal'] ?? ''), accountId, sourceId })
		if (sourceId === 'missing') return send(404, { title: 'No such transaction' })
		if (sourceId === 'slow') {
			await new Promise<void>(resolve => {
				const timer = setTimeout(resolve, 2000)
				response.once('close', () => {
					clearTimeout(timer)
					resolve()
				})
			})
			if (response.destroyed) return
		}
		if (sourceId === 'malformed') return send(200, { amount: 'not-a-transaction' })
		if (sourceId === 'oversized') return send(200, { padding: 'x'.repeat(20_000) })
		if (!['legacy-001', 'slow', 'wrong-account', 'wrong-id'].includes(sourceId))
			return send(404, { title: 'No such transaction' })
		send(200, {
			source_id: sourceId === 'wrong-id' ? 'different-id' : sourceId,
			account_ref: sourceId === 'wrong-account' ? 'account-c' : accountId,
			booked_at: '2026-01-15T12:00:00.000Z',
			amount: tenantId === 'tenant-north' ? '125.40' : '99.00',
			currency: 'EUR',
			dc: 'D',
		})
	})
	return { server, requests }
}

if (process.argv[1] && import.meta.url === pathToFileURL(process.argv[1]).href) {
	const { server } = createLegacyBankMock()
	const hostname = process.env.MOCK_HOST ?? '127.0.0.1'
	const port = Number(process.env.MOCK_PORT ?? 4010)
	server.listen(port, hostname, () => process.stdout.write('Legacy bank mock is listening\n'))
	process.once('SIGTERM', () => server.close())
	process.once('SIGINT', () => server.close())
}
```

The mock accepts two deliberately public test credentials. Each maps to a
different tenant. The same account and record ID return 125.40 EUR in the
north tenant and 99.00 EUR in the south tenant. This makes a mistaken credential
selection visible.

The special IDs `missing`, `malformed`, `oversized`, `wrong-account`,
`wrong-id`, and `slow` are controlled failure fixtures. They let us test
what happens before any posting is attempted.

## Run the dependency

Create `compose.yaml` in your application root:

```yaml title="compose.yaml"
services:
  legacy-bank:
    image: node:24-bookworm@sha256:934240a162082fd8b8a2f90cd5114446443f1eba1c5378f6687167ca405e6584
    user: node
    working_dir: /app
    command: ["node", "/app/server.ts"]
    environment:
      MOCK_HOST: 0.0.0.0
      MOCK_PORT: "4010"
    volumes:
      - ./src/mockLegacyBank.ts:/app/server.ts:ro
    ports:
      - "127.0.0.1:4010:4010"
    read_only: true
    cap_drop: [ALL]
    security_opt: ["no-new-privileges:true"]
    healthcheck:
      test: ["CMD", "node", "-e", "fetch('http://127.0.0.1:4010/health').then(r => { if (!r.ok) process.exit(1) }).catch(() => process.exit(1))"]
      interval: 2s
      timeout: 2s
      retries: 10
```

The image is pinned to a verified digest. Node runs this dependency's
TypeScript file directly; the mock uses only Node built-ins and syntax that
its TypeScript support can erase. No framework installation is needed inside
this container.

The source mount and container filesystem are read-only. The published port
binds to your machine's loopback address. The health check waits for the HTTP
route to respond before Compose reports success.

```bash title="Start the isolated legacy-bank dependency"
docker compose -p example-bank-legacy up -d --wait
curl --fail http://127.0.0.1:4010/health
curl --fail -H 'authorization: Bearer mock-north' \
  'http://127.0.0.1:4010/transactions/legacy-001?accountId=account-a'
```

Expect `{"status":"ok"}` from health and the north-tenant legacy record
from the second request. Docker with Compose is required for this path.
Keep the container running while building the client.

Without Docker, run `node src/mockLegacyBank.ts` in a separate terminal
using Node 24.15 or newer. Keep it running; use Ctrl+C to stop it. Use one
startup method at a time because both listen on port 4010.

These fixture credentials are not secrets and provide no production security.
The mock's principal header is diagnostic only; its credential selects the
tenant. Next, [write the application’s outbound client](/tutorials/banking-integrations/add-legacy-client/).
