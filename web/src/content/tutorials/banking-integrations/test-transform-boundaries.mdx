Keep boundary tests small and observable. The runnable example confirms that
Dana imports the fixed legacy debit, Bob receives `403`, and the account history
contains the normalized source ID.

```ts title="src/banking.integration.test.ts"
expect(imported.status).toBe(200)
expect(denied.status).toBe(403)
expect(statement.transactions).toContainEqual(
  expect.objectContaining({ sourceTransactionId: 'legacy-bank-debit-a-1' }),
)
```

Add a unit test for invalid monetary strings, an HTTP test for the complete
command, and a CSV test that proves `text/csv` is returned only after the
result-scope guard passes.

```bash title="Verify the complete local example"
npm run typecheck
npm test
```

The mock stays in process. Add Docker Compose only when a tutorial needs a real
protocol, persistence, or multi-process behaviour. This first adapter remains
fast to run and safe to repeat.
