title: "Generate the legacy import command"
description: "Use the CLI to create a command, then connect wire validation, input transformation, business guards, and a downstream posting call."

---

Run the generator inside your application:

```bash title="Generate importLegacyTransaction"
npm run add:command -- import-legacy-transaction \
  --service banking --service-version 1 \
  --description "Import a supported legacy transaction through the posting command" \
  --non-interactive
```

The CLI creates `command/importLegacyTransaction/` below
`src/service/banking/v1/` and registers the command in
`bankingV1Service.ts`. Keep that generated registration and `types.ts`.
Replace the generated schema:

```ts title="src/service/banking/v1/command/importLegacyTransaction/schema.ts"
import { z } from 'zod'
import { recordedTransactionSchema, transactionInputSchema } from '../../../../../transaction.js'

export const bankingV1ImportLegacyTransactionInputPayloadSchema = transactionInputSchema
export const bankingV1ImportLegacyTransactionInputParameterSchema = z.object({})
export const bankingV1ImportLegacyTransactionOutputPayloadSchema = recordedTransactionSchema
```

These are the **domain** schemas used by the handler. The legacy schema is
attached separately to the input transform. Replace the builder:

```ts title="src/service/banking/v1/command/importLegacyTransaction/importLegacyTransactionCommandBuilder.ts"
import { requirePostingAccess } from '../../../../../accountGuards.js'
import { fromLegacyTransaction, legacyTransactionSchema } from '../../../../../legacyTransaction.js'
import { bankingV1ServiceBuilder } from '../../bankingV1ServiceBuilder.js'
import {
	bankingV1RecordTransactionInputParameterSchema,
	bankingV1RecordTransactionInputPayloadSchema,
	bankingV1RecordTransactionOutputPayloadSchema,
} from '../recordTransaction/schema.js'
import {
	bankingV1ImportLegacyTransactionInputParameterSchema,
	bankingV1ImportLegacyTransactionInputPayloadSchema,
	bankingV1ImportLegacyTransactionOutputPayloadSchema,
} from './schema.js'

export const importLegacyTransactionCommandBuilder = bankingV1ServiceBuilder
	.getCommandBuilder('importLegacyTransaction', 'Import a supported legacy transaction through the posting command')
	.addPayloadSchema(bankingV1ImportLegacyTransactionInputPayloadSchema)
	.addParameterSchema(bankingV1ImportLegacyTransactionInputParameterSchema)
	.addOutputSchema(bankingV1ImportLegacyTransactionOutputPayloadSchema)
	.exposeAsHttpEndpoint('POST', 'legacy-transactions')
	.setTransformInput(
		legacyTransactionSchema,
		bankingV1ImportLegacyTransactionInputParameterSchema,
		async function (_context, payload, parameter) {
			return { payload: fromLegacyTransaction(payload), parameter }
		},
	)
	.setBeforeGuardHooks({ postingAccess: requirePostingAccess })
	.canInvoke(
		'Banking',
		'1',
		'recordTransaction',
		bankingV1RecordTransactionOutputPayloadSchema,
		bankingV1RecordTransactionInputPayloadSchema,
		bankingV1RecordTransactionInputParameterSchema,
	)
	.setCommandFunction(async function (context, payload, parameter) {
		return context.service.Banking['1'].recordTransaction(payload, parameter)
	})
```

`setTransformInput` receives the raw payload schema, raw parameter schema,
and the conversion function. The function returns both `payload` and
`parameter`, even though only the payload changes. Use a normal
`async function`: PURISTA binds these hooks to the service instance and
rejects arrow functions for this hook.

After transformation and domain validation, `postingAccess` checks the
normalized `accountId`. The handler then invokes the existing
`recordTransaction` command through `context.service`. That command still
runs its own guard and repository check. We do not create a second write path.

The `canInvoke` declaration uses the downstream command's schemas.
Here the callee accepts native domain input. Later, when another command
calls this import command, it will need the legacy **wire** schema instead.
