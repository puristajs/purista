Learn how to build with PURISTA, one capability at a time. Each chapter starts
with a Framework task, shows the code you write, tests the boundary with PURISTA
helpers, and ends with a result you can run.

Example Bank is the application name used throughout the course. It is never a
service boundary. The composition root assembles the application and Hono
provides HTTP transport. Each service owns one focused capability:
`BankProfile` provides the public example profile, `Identity` owns login and
sessions, `Transaction` owns transaction commands and rules, `Monitoring` owns
reactions to transaction facts, `Reporting` owns background reports, `Support`
owns support conversations, and `Knowledge` owns ingestion and retrieval.
Repositories, model providers, and external clients are injected resources.

One UI, a few invented records, and safe actions make Framework behavior
visible. You do not need banking knowledge. The example does not implement
payments, balances, accounting, or regulatory controls.

## Course structure

### Foundations

The first chapters teach you how to:

1. create a PURISTA project with the CLI;
2. use the PURISTA Hono webserver;
3. serve a static React application;
4. expose commands as REST endpoints;
5. inject a database resource;
6. protect generated endpoints;
7. handle opaque sessions with StateStore;
8. authorize business actions with guards;
9. transform command input and output; and
10. inject and mock external resources.

### Messaging and background work

Continue with named command result events, subscriptions, streams, queues,
queue workers, schedules, typed metrics, and tracing. The bank fixture remains
small: one transaction fact, one monitoring signal, and one short statement.

### Add AI capabilities

The AI path keeps native Harness definitions and PURISTA orchestration as
separate layers. A service mounts one composed Harness definition. Commands,
streams, queues, and workers consume published agents and workflows through
versioned EventBridge addresses. Provider credentials and runtime adapters stay
in the application composition root.

The AI path adds structured classification, AI guardrails, a complete
RAG pipeline, standard browser streaming, memory, PURISTA-backed tools, Skills,
human review, parallel agents, workflows, sandboxing, and evaluation. The RAG
chapter covers ingestion and retrieval together: Harness supplies the embedding
model for both sides, while PURISTA owns authorization, persistence, the
command-backed search tool, and the HTTP stream. Chapters under active review
remain visible with a **Draft preview** label so their sequence and examples can
be reviewed on the website.

## How every chapter works

Each root topic has nested **Build** and **Test with PURISTA** pages, plus small
optional extensions where they help. The main path uses project-local PURISTA
CLI commands, complete located edits, easy English, and focused tests. Every
published chapter has independently runnable source under `examples/banking`
and a replay from a clean consumer project.

Every chapter stays linked from the course while it is reviewed. The draft
label is removed only after its tutorial steps, source, tests, runtime behavior,
and navigation pass together.
