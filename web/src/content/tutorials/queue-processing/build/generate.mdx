A queue belongs to one versioned service. Create `Reporting` because it owns
background report jobs and their operational results.

```bash title="Generate the Reporting service" replay="project"
npm run add:service -- reporting \
  --description "Generate background reports" --non-interactive
```

Now generate the queue. `add:queue` creates the queue contract, its first worker,
tests, inferred types, and service registration together.

```bash title="Generate the queue and worker" replay="project"
npm run add:queue -- generate-statement \
  --service reporting --service-version 1 \
  --description "Generate one transaction statement" \
  --worker-name generate-statement-worker \
  --worker-description "Build one transaction statement" \
  --worker-mode continuous --max-parallel-handlers 1 \
  --without-producer --non-interactive
```

Use `add:queue-worker` later only when the same queue deliberately needs another
eligible worker definition. One worker is enough here.

## Define the small business fixture

The policy below checks a real business action: whether this principal may
create a statement for this account. Authentication has already established
who the principal is.

```ts title="src/service/reporting/v1/reportAccess.ts" write
export type ReportAccess = {
	tenantId: string
	principalId: string
	accountId: string
}

export function canGenerateStatement(access: ReportAccess) {
	return access.tenantId === 'tenant-example'
		&& access.principalId === 'principal-alex'
		&& access.accountId === 'account-operating'
}
```

The worker result is intentionally small and contains invented data only.

```ts title="src/service/reporting/v1/statement.ts" write
import { z } from 'zod'

export const generatedStatementSchema = z.strictObject({
	accountId: z.string().trim().min(1),
	transactionId: z.uuid(),
	amountCents: z.number().int().positive(),
	direction: z.enum(['credit', 'debit']),
	counterparty: z.string().trim().min(2).max(80),
	generatedAt: z.iso.datetime(),
})

export type GeneratedStatement = z.output<typeof generatedStatementSchema>
```

## Replace the generated queue contract

```ts title="src/service/reporting/v1/queue/generateStatement/schema.ts" write
import { z } from 'zod'

export const reportingV1GenerateStatementQueuePayloadSchema = z.strictObject({
	accountId: z.string().trim().min(1),
	transactionId: z.uuid(),
})

export const reportingV1GenerateStatementQueueParameterSchema = z.object({})
```

```ts title="src/service/reporting/v1/queue/generateStatement/generateStatementQueueBuilder.ts" write
import { reportingV1ServiceBuilder } from '../../reportingV1ServiceBuilder.js'
import {
	reportingV1GenerateStatementQueuePayloadSchema,
	reportingV1GenerateStatementQueueParameterSchema,
} from './schema.js'

export const generateStatementQueueBuilder = reportingV1ServiceBuilder
	.getQueueBuilder('generateStatement', 'Generate one transaction statement')
	.addPayloadSchema(reportingV1GenerateStatementQueuePayloadSchema)
	.addParameterSchema(reportingV1GenerateStatementQueueParameterSchema)
	.setLifecycleConfig({ maxAttempts: 3 })
	.setResultPolicy({ mode: 'state', delivery: 'required', ttlMs: 15 * 60 * 1000 })
	.setBeforeEnqueueTransform(async function (_context, payload, parameter) {
		const parsed = reportingV1GenerateStatementQueuePayloadSchema.parse(payload)
		return {
			payload: { ...parsed, accountId: parsed.accountId.trim() },
			parameter,
		}
	})
```

The queue schema validates Framework-mediated enqueue calls. The transform
normalizes after validation, so it parses the unknown transform input before
using it. Three attempts keep the local example bounded. `mode: 'state'` asks
the worker runtime to write its result through a configured `QueueJobStore`.

```ts title="src/service/reporting/v1/queue/generateStatement/generateStatementQueueBuilder.test.ts" write
import { expect, test } from 'vitest'
import { generateStatementQueueBuilder } from './generateStatementQueueBuilder.js'

test('declares the queue contract and bounded local retry policy', async () => {
	const definition = await generateStatementQueueBuilder.getDefinition()
	expect(definition.queueName).toBe('generateStatement')
	expect(definition.lifecycle).toMatchObject({ maxAttempts: 3 })
	expect(definition.resultPolicy).toMatchObject({
		mode: 'state', delivery: 'required', ttlMs: 15 * 60 * 1000,
	})
})
```

## Keep the first worker executable

The generated worker API currently receives broker payload as unknown. Parse it
at the worker boundary. This first implementation proves the queue lifecycle;
the real Transaction invocation arrives on the worker page.

```ts title="src/service/reporting/v1/queue-worker/generateStatementWorker/generateStatementWorkerQueueWorkerBuilder.ts" write
import { reportingV1ServiceBuilder } from '../../reportingV1ServiceBuilder.js'
import { reportingV1GenerateStatementQueuePayloadSchema } from '../../queue/generateStatement/schema.js'

export const generateStatementWorkerQueueWorkerBuilder = reportingV1ServiceBuilder
	.getQueueWorkerBuilder('generateStatement', 'Build one transaction statement')
	.setMode('continuous')
	.setMaxParallelHandlers(1)
	.setHandler(async function (_context, message) {
		const payload = reportingV1GenerateStatementQueuePayloadSchema.parse(message.payload)
		return {
			status: 'success' as const,
			output: {
				...payload,
				amountCents: 1,
				direction: 'credit' as const,
				counterparty: 'Pending statement source',
				generatedAt: new Date().toISOString(),
			},
		}
	})
```

```ts title="src/service/reporting/v1/queue-worker/generateStatementWorker/generateStatementWorkerQueueWorkerBuilder.test.ts" write
import { createQueueWorkerTestHarness } from '@purista/core'
import { expect, test, vi } from 'vitest'
import { reportingV1Service } from '../../reportingV1Service.js'
import { generateStatementWorkerQueueWorkerBuilder } from './generateStatementWorkerQueueWorkerBuilder.js'

test('acknowledges a valid job through the worker runtime', async () => {
	const payload = {
		accountId: 'account-operating',
		transactionId: '3bd00f72-8db0-4f39-875d-fd5e251a7f32',
	}
	const set = vi.fn().mockResolvedValue(undefined)
	const harness = await createQueueWorkerTestHarness(reportingV1Service, generateStatementWorkerQueueWorkerBuilder, {
		queueJobStore: { get: vi.fn(), set },
	})
	try {
		const result = await harness.run({
			id: 'job-1', queueName: 'generateStatement', payload, parameter: {}, headers: {},
			createdAt: Date.now(), attempt: 1, maxAttempts: 3,
			leaseExpiresAt: Date.now() + 60_000, leaseTtlMs: 60_000,
		})
		expect(result.ackCalls).toHaveLength(1)
		expect(set).toHaveBeenCalledWith(expect.objectContaining({
			status: 'success', result: expect.objectContaining(payload),
		}), 15 * 60 * 1000)
	} finally {
		await harness.destroy()
	}
})
```

`createQueueWorkerTestHarness` executes one lease through PURISTA. A successful
returned result is stored first and then acknowledged. Always destroy the
harness so its service and mock bridges stop cleanly.
