Do not hand-write the stream folder. The local CLI creates the files in the
same shape as every other PURISTA service artifact.

```bash title="Generate analyzeTransaction"
npm run add:stream -- analyze-transaction --description "Stream a short, bounded transaction review" --service banking-operations --service-version 1
```

Run this command from the root of the project created by
`npm create purista@latest`. The generated project installs `@purista/cli`
and exposes it through `add:stream`, so no global CLI installation is needed.

## Read the generated checkpoint

With the default camel-case convention, the command creates:

```text title="Generated stream files"
src/service/bankingOperations/v1/stream/analyzeTransaction/
  analyzeTransactionStreamBuilder.ts
  analyzeTransactionStreamBuilder.test.ts
  schema.ts
  types.ts
```

It also imports the builder and adds
`analyzeTransactionStreamBuilder.getDefinition()` to the
`streamDefinitions` list in the `bankingOperations` service aggregate. A
builder file by itself is not a running service definition.

The generated schemas are intentionally permissive placeholders and the
handler only calls `writer.close()`. That is a safe starting shape, not the
finished banking behavior. The next pages replace the placeholders with small
contracts and a real business check.

## Prove the generated files compile

The generated test uses `createStreamTestHarness`. Run it before editing so a
failure later points to your change rather than the CLI setup.

```bash title="Run the generated stream test"
npm test -- --run src/service/bankingOperations/v1/stream/analyzeTransaction/analyzeTransactionStreamBuilder.test.ts
```

The repository reference composes the same behavior in
`examples/banking/src/advanced/service.ts`:

```bash title="Run the reference checkpoint"
npm run test -w @purista/banking-tutorials -- src/advanced/service.test.ts
```
