---
title: Protect the stream
description: Add an account-level guard before the stream looks up or sends any transaction information.
order: 63
---

Generate or confirm the stream before adding its guard:

```bash title="Generate analyzeTransaction"
npm run add:stream -- analyze-transaction --description "Stream a short, bounded transaction review" --service banking-operations --service-version 1
```

Authentication answers who sent the request. This guard answers a different
business question: **may this verified person read this account?** Put that
decision before the handler, so an unauthorized caller receives no progress
chunk and the handler never looks up the transaction.

First make the repository a declared service resource. The final bank example
uses `BankingRepository.canRead(principalId, accountId)`; your project can use
the same small interface:

```ts title="bankingOperationsV1ServiceBuilder.ts"
export const bankingOperationsV1ServiceBuilder = new ServiceBuilder(serviceInfo)
  .defineResource<'bankingRepository', BankingRepository>()
```

Then add a named before guard to the generated stream builder. Use `function`,
not an arrow function, because PURISTA binds the builder callback to its service
instance.

```ts title="analyzeTransactionStreamBuilder.ts"
.setBeforeGuardHooks({
  accountRead: async function (context, payload) {
    const allowed = context.resources.bankingRepository.canRead(
      context.message.principalId,
      payload.accountId,
    )
    if (!allowed) {
      throw new HandledError(StatusCode.Forbidden, 'You may not read this account')
    }
  },
})
```

Import `HandledError` and `StatusCode` from `@purista/core`. Do not accept a
principal or tenant ID from the stream payload. The server creates trusted
message identity, and the guard uses that identity with the requested business
object.

```bash title="Test the authorized starting path"
npm test -- --run src/service/bankingOperations/v1/stream/analyzeTransaction/analyzeTransactionStreamBuilder.test.ts
```

The reference implementation keeps this guard in
`examples/banking/src/advanced/service.ts`. Next, make its writer produce the
three visible progress updates.
