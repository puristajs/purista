Skill text gives the model reviewed guidance. It does not decide whether the
authenticated principal may use that guidance for a support case. Keep
authentication and business authorization in PURISTA code before model or
sandbox work begins.

## Declare the case policy

Create the resource contract. A production implementation can check tenant
ownership, case assignment, and case state.

```ts title="src/service/support/v1/SupportProcedurePolicy.ts" write
export interface SupportProcedurePolicy {
	canAnswer(input: Readonly<{ tenantId: string; principalId: string; caseId: string }>): Promise<boolean>
}
```
Use one helper at every reachable boundary. The session id correlates Harness
history; it does not grant access and does not expose raw identity in a storage
key.

```ts title="src/service/support/v1/requireSupportProcedureAccess.ts" write
import { createHash } from 'node:crypto'
import { HandledError, StatusCode } from '@purista/core'
import type { SupportProcedurePolicy } from './SupportProcedurePolicy.js'

export async function requireSupportProcedureAccess(
	policy: SupportProcedurePolicy,
	identity: Readonly<{ tenantId?: string; principalId?: string }>,
	caseId: string,
) {
	if (!identity.tenantId || !identity.principalId)
		throw new HandledError(StatusCode.Unauthorized, 'A valid session is required')
	if (!(await policy.canAnswer({ tenantId: identity.tenantId, principalId: identity.principalId, caseId }))) {
		throw new HandledError(StatusCode.Forbidden, 'This support procedure is not available')
	}
}

export function supportProcedureSessionId(
	identity: Readonly<{ tenantId?: string; principalId?: string }>,
	caseId: string,
) {
	if (!identity.tenantId || !identity.principalId)
		throw new HandledError(StatusCode.Unauthorized, 'A valid session is required')
	const digest = createHash('sha256')
		.update(JSON.stringify(['support-procedure-v1', identity.tenantId, identity.principalId, caseId]))
		.digest('hex')
	return `support-procedure:${digest}`
}
```
Declare the resource on the owning service builder. The concrete policy is
provided by the application composition root.

```ts title="src/service/support/v1/supportV1ServiceBuilder.ts" write
import { ServiceBuilder } from '@purista/core'
import type { SupportProcedurePolicy } from './SupportProcedurePolicy.js'

export const supportV1ServiceBuilder = new ServiceBuilder({
	serviceName: 'Support',
	serviceVersion: '1',
	serviceDescription: 'Owns support procedure answers',
}).defineResource<'supportProcedurePolicy', SupportProcedurePolicy>()
```
## Guard the mounted target

Replace the generated Harness composition with one service-owned definition and
one policy object. The mounted agent can be addressed directly, so it has its
own guard. The agent input contains only `caseId`; identity comes from the
trusted PURISTA invocation message.

```ts title="src/service/support/v1/harness/supportHarness.ts" write
import type { HarnessBusinessGuardContext } from '@purista/core'
import { defineHarness } from '@purista/harness'
import type { z } from 'zod'
import { requireSupportProcedureAccess } from '../requireSupportProcedureAccess.js'
import type { SupportProcedurePolicy } from '../SupportProcedurePolicy.js'
import { supportV1ServiceBuilder } from '../supportV1ServiceBuilder.js'
import { answerProcedureQuestionAgent } from './agent/answerProcedureQuestion/answerProcedureQuestionAgent.js'

export const supportHarness = defineHarness({ name: 'support', revision: 'support-v1' }).addAgent(
	answerProcedureQuestionAgent,
)

export const supportHarnessPolicy = supportV1ServiceBuilder.defineHarnessPolicy(supportHarness, {
	agents: {
		answerProcedureQuestion: {
			beforeGuards: {
				procedureAccess: async (
					context: HarnessBusinessGuardContext<{ supportProcedurePolicy: SupportProcedurePolicy }>,
					input: z.output<typeof answerProcedureQuestionAgent.contract.input>,
				) => requireSupportProcedureAccess(context.resources.supportProcedurePolicy, context.identity, input.caseId),
			},
		},
	},
	workflows: {},
})
```
The guard is the authorization boundary. The Skill can recommend a safe
procedure, but it cannot bypass this check, add a command, or execute a script.
The agent exposes only the read capability, so files under the Skill directory
remain data.

