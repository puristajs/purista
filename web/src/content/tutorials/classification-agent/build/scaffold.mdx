Start in an empty parent directory. This chapter creates a complete application
named `support-classification`.

```bash title="Create and enter the classification project" replay="parent"
npm create purista@3.0.0 support-classification -- --runtime node --event-bridge default --non-interactive --defaults
cd support-classification
```

Install the published v4 packages used by the example. The OpenAI adapter is
needed only for the optional live entry point.

```bash title="Install Framework, Harness, and test dependencies" replay="project"
npm install @purista/core@^4.0.0 @purista/harness@^4.0.0 @purista/harness-openai@^4.0.0 zod@^4.4.3
npm install --save-dev @purista/cli@^4.0.0 @biomejs/biome@^2.5.8 @types/node@^26.2.0 @types/sinon@^22.0.0 sinon@^22.1.0 tsx@^4.23.12 typescript@npm:@typescript/typescript6@^6.0.2 vitest@^4.1.10
```

Generate the service and agent with explicit non-interactive values.

```bash title="Generate Support and its classification agent" replay="project"
npm run add:service -- support --description "Classify and route customer support requests" --non-interactive
npm run add:agent -- classify-support-message --service support --service-version 1 --description "Classify one support message with a structured result" --non-interactive --model-alias classification
```

The service owns its Harness files:

```text title="Service-owned agent structure"
src/service/support/v1/
├── harness/
│   ├── agent/classifySupportMessage/
│   │   ├── classifySupportMessageAgent.ts
│   │   └── classifySupportMessageAgent.test.ts
│   └── supportHarness.ts
└── supportV1Service.ts
```

The agent definition contains portable AI behavior. `supportHarness.ts`
assembles the definitions owned by this service and declares the mount policy.
The service contains one `.mountHarness(...)` call.

```bash title="Verify the generated checkpoint" replay="project"
npm run build
npm test
```
