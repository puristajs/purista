An evaluation answers a practical question: did this candidate produce the behavior your application expects? In this chapter you build a versioned dataset, run the native Harness agent for every case, score its structured output, and fail a change gate when the result regresses.

The Example Bank supplies three short support messages. The framework pieces are the focus: the agent belongs to the Support service version, the model is bound at startup, and the production command reaches the mounted target by its address through EventBridge.

```text title="Evaluation and application paths"
versioned dataset -> native Harness agent -> scorers -> change gate
                                      \\
PURISTA command -> Support / 1 / runClassifySupportMessage -> same agent
```

The default provider is a strict fake. It needs no credentials and proves the evaluation pipeline. A separate live command can measure a named provider candidate. A scripted provider cannot measure model quality.
