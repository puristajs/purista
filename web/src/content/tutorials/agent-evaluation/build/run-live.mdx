Create a separate live runner so credentials and provider variability never
enter the default verification path.

```ts title="src/runLiveEvaluation.ts" write
import { openai } from '@purista/harness-openai'
import { assertClassificationGate } from './changeGate.js'
import { runClassificationEvaluation } from './runClassificationEvaluation.js'

async function main() {
	const apiKey = process.env.OPENAI_API_KEY?.trim()
	if (!apiKey) throw new Error('OPENAI_API_KEY is required to run the live evaluation.')
	const model = process.env.OPENAI_MODEL?.trim() || 'gpt-5-mini'
	const result = await runClassificationEvaluation(openai({ apiKey }), {
		model,
		runId: `support-classification-live-${Date.now()}`,
	})
	const gate = assertClassificationGate(result)
	process.stdout.write(`${JSON.stringify({ status: result.status, model, gate }, null, 2)}\n`)
}

main().catch((error: unknown) => {
	process.stderr.write(`${error instanceof Error ? error.message : 'Live evaluation failed.'}\n`)
	process.exit(1)
})
```

Document the required environment values.

```dotenv title=".env.example" write
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5-mini
```

Copy `.env.example` to `.env`, choose the model candidate deliberately, and run
the live evaluation.

```bash title="Run the optional live candidate"
node --env-file=.env --import tsx src/runLiveEvaluation.ts
```

Record the exact provider, model, prompt/module version, dataset version, and
scorer versions beside every result. A live score without candidate identity
cannot support a release decision.
