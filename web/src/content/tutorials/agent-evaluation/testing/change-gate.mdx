A gate must fail when the evaluation did not complete cleanly, even if some
available case scores look good. Then compare the all-cases aggregate for each
required dimension.

```ts title="src/changeGate.ts"
export function assertClassificationGate(
	result: EvaluationRunResult,
	thresholds: ClassificationGateThresholds = { categoryRate: 1, urgencyRate: 1 },
) {
	if (result.status !== 'completed') throw new Error(`Evaluation did not complete cleanly: ${result.status}`)
	const categoryRate = passRate(result, 'category_exact')
	const urgencyRate = passRate(result, 'urgency_exact')
	if (categoryRate < thresholds.categoryRate || urgencyRate < thresholds.urgencyRate) {
		throw new Error(
			`Classification gate failed: category=${categoryRate.toFixed(3)}, urgency=${urgencyRate.toFixed(3)}`,
		)
	}
	return { categoryRate, urgencyRate }
}
```

The evaluation suite has one passing scripted candidate and one intentional
regression. Both execute the real portable agent with strict fake providers.
The second case proves the gate throws when category accuracy drops.

Test the PURISTA application separately. A focused command test injects the
classification policy and mocked declared agent client, then asserts the
caller-scoped session id. The EventBridge suite proves a successful command
crosses both business guards and a denied direct-agent invocation reaches no
model call.

For a production release gate, also inspect critical segment thresholds,
scorer errors, latency, token use, cost, guardrail behavior, citation
grounding, tool trajectories, and required workflow steps. Keep threshold
changes under review rather than weakening them automatically when a candidate
fails.

```bash title="Verify the evaluation chapter" replay="project"
npm run build
npm test
npm run lint
npm run evaluate
npm run demo
```

`npm run evaluate` uses scripted outputs and prints a deterministic passing
gate. `npm run demo` invokes the mounted agent through a real EventBridge. Both
need no API key. They prove execution wiring, not live model quality.

Run a provider candidate only when you intentionally want a live quality
measurement. Record the provider and model version with the result, review
cost and data policy first, and expect a non-zero exit when the gate fails.

```bash title="Run the optional live candidate" replay="project"
cp .env.example .env
npm run evaluate:live
```
