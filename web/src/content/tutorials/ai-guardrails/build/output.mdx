An output rail receives the schema-valid final candidate after the model loop.
It does not inspect intermediate tool results. This action replaces one narrow
digit pattern in the classification reason while preserving the structured
object.

## Define the output transform

Create the complete action file.

```ts title="src/harness/support/agent/classifySupportMessage/classificationOutputGuardrail.ts" write
import { defineGuardrailAction } from '@purista/harness-guardrails'
import { classifySupportMessageOutputSchema } from './schema.js'

const cardLikeDigits = /\b\d{13,19}\b/g

export const redactCardLikeDigits = defineGuardrailAction({
	phase: 'output',
	valueSchema: classifySupportMessageOutputSchema,
	evaluate: ({ value }) => {
		const reason = value.reason.replace(cardLikeDigits, '[redacted]')
		return reason === value.reason
			? { decision: 'allow' }
			: {
					decision: 'transform',
					target: 'bot_message',
					value: { ...value, reason },
					reasonCode: 'card_digits_redacted',
				}
	},
})
```
The transform target must match the phase: `bot_message` for output. The
replacement object must still satisfy both the action value schema and agent
output schema. Guardrails do not search arbitrary nested fields; this action
explicitly owns `reason`.

## Compose the ordered flows

Create the policy file. Flow names refer to keys in `actions`, which makes the
execution order visible and reviewable.

```ts title="src/harness/support/agent/classifySupportMessage/classificationGuardrails.ts" write
import { defineGuardrails } from '@purista/harness-guardrails'
import { blockInstructionOverride } from './classificationInputGuardrail.js'
import { redactCardLikeDigits } from './classificationOutputGuardrail.js'

export const classificationGuardrails = defineGuardrails({
	config: {
		rails: {
			input: { flows: ['block instruction override'] },
			output: { flows: ['redact card-like digits'] },
		},
	},
	actions: {
		'block instruction override': blockInstructionOverride,
		'redact card-like digits': redactCardLikeDigits,
	},
	actionTimeoutMs: 2_000,
})
```
## Replace the generated agent

Replace the complete generated agent file. The `guardrails` property attaches
the compiled flows to the default-loop agent lifecycle.

```ts title="src/harness/support/agent/classifySupportMessage/classifySupportMessageAgent.ts" write
import { type BuilderState, defineHarnessModule, type ModelAlias } from '@purista/harness'
import { classificationGuardrails } from './classificationGuardrails.js'
import { classifySupportMessageInputSchema, classifySupportMessageOutputSchema } from './schema.js'

type PrimaryModelState = BuilderState & { models: { primary: ModelAlias } }

export const classifySupportMessageAgent = defineHarnessModule<PrimaryModelState>()(
	'support.agent.classify-support-message',
	{
		version: '1.0.0',
		register(builder) {
			return builder.agent('classify_support_message', {
				model: 'primary',
				input: classifySupportMessageInputSchema,
				output: classifySupportMessageOutputSchema,
				updates: 'object-snapshot',
				instructions: 'Classify the support message and give one concise reason grounded in its text.',
				guardrails: classificationGuardrails,
			})
		},
	},
)
```
Automatic Guardrails attach to default-loop agents because Harness owns their
model and tool lifecycle. A custom agent `handler` owns its own release
boundaries and cannot also set `guardrails`.

This digit expression is only a synthetic teaching detector. Production
privacy controls need reviewed detectors, representative evaluation data,
retention rules, and the appropriate optional adapter.
