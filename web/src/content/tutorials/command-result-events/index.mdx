A PURISTA command always returns a response to its caller. When other
components should also react to the completed result, the command can give that
successful response an event name.

This chapter uses two event forms for two different meanings:

- `transaction.recorded.v1` names the final, validated result of
  `recordTransaction`;
- `transaction.recording.started.v1` is a separate fact emitted while the
  handler runs.

The successful result is not emitted manually. PURISTA creates it only after
the command handler, output validation, and guards have completed. The custom
event is declared with its own schema and emitted at the exact line where its
fact becomes true.
