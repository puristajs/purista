The command, workflow, and stream are complete. Now assemble their runtime
dependencies. Keep transport, session ownership, and retrieval storage in
their proper boundaries:

- `Identity` owns login and opaque session records in PURISTA `StateStore`;
- `Knowledge` owns search authorization, retrieval, and the mounted Harness;
- the PostgreSQL repository is an injected Knowledge resource;
- Hono authenticates protected generated endpoints and forwards trusted
  identity to EventBridge; and
- the React bundle uses the public login command and protected Knowledge
  stream. There is no handwritten chat endpoint.

Install the runtime packages by their published names.

```bash title="Install Hono, PostgreSQL, and the TypeScript runner" replay="project"
npm install --save-exact @purista/hono-http-server@4.0.0 @hono/node-server@2.1.0 pg@8.23.0
npm install --save-dev --save-exact @types/pg@8.23.1 tsx@4.23.12
```

Use a normal public PURISTA command for login. The command validates local
credentials and writes only the resulting session to StateStore. It does not
put passwords or identity claims into browser-controlled headers.

```ts title="src/service/identity/v1/command/login/loginCommandBuilder.ts"
export const loginCommandBuilder = identityV1ServiceBuilder
	.getCommandBuilder('login', 'Create a local tutorial session')
	.addPayloadSchema(inputSchema)
	.addOutputSchema(outputSchema)
	.exposeAsHttpEndpoint('POST', 'session/login')
	.makeEndpointPublic()
	.setCommandFunction(async function (context, payload) {
		if (payload.username !== 'alex@example.test' || payload.password !== 'demo-password') {
			throw new HandledError(StatusCode.Unauthorized, 'Invalid local credentials')
		}
		const sessionToken = randomUUID()
		const displayName = 'Alex Example'
		const expiresAt = Date.now() + this.config.sessionTtlMs
		await context.states.setState(sessionStateKey(sessionToken), {
			principalId: 'principal-alex',
			tenantId: 'tenant-example',
			displayName,
			expiresAt,
		})
		return { sessionToken, displayName, expiresAt }
	})
```

The Hono protection hook resolves the opaque token through the internal
`Identity / 1 / resolveSession` command. Only the returned server-side identity
is added to the Hono context. A `HandledError` becomes the standard Problem
Details response through Hono's default error handler.

```ts title="src/sessionProtectMiddleware.ts"
import { HandledError, StatusCode } from '@purista/core'
import type { EndpointProtectMiddleware, HonoServiceClass } from '@purista/hono-http-server'
import type { SessionRecord } from './service/identity/v1/session.js'

export const createSessionProtectMiddleware = (http: HonoServiceClass): EndpointProtectMiddleware<HonoServiceClass> =>
	async function (context, next) {
		const authorization = context.req.header('authorization')
		const sessionToken = authorization?.match(/^Bearer\s+(.+)$/i)?.[1]
		if (!sessionToken) throw new HandledError(StatusCode.Unauthorized, 'A session bearer token is required')

		try {
			const session = (await http.invoke(
				{
					receiver: { serviceName: 'Identity', serviceVersion: '1', serviceTarget: 'resolveSession' },
					payload: { payload: undefined, parameter: { sessionToken } },
					contentType: 'application/json',
					contentEncoding: 'utf-8',
				},
				'protect-session',
			)) as SessionRecord
			context.set('principalId', session.principalId)
			context.set('tenantId', session.tenantId)
			context.set('additionalParameter', { sessionToken })
			await next()
		} catch {
			throw new HandledError(StatusCode.Unauthorized, 'The session is invalid or expired')
		}
	}
```

Create all services in one composition root. `setProtectMiddleware` applies to
the protected stream because its builder called `enableHttpSecurity(true)`.
`registerService` projects the public login command and protected Knowledge
stream from their definitions. Static routes are added only for the UI files.

```ts title="src/createKnowledgeApplication.ts"
http.setProtectMiddleware(createSessionProtectMiddleware(http))
await identity.start()
await knowledge.start()
http.registerService(identity, knowledge)
registerStaticWebsite(http)
await http.start()
```

Build the UI before starting the server, then run the application.

```bash title="Start the complete knowledge application" replay="project"
cp .env.example .env
docker compose up -d --wait
npm run build
npm start
```

Open `http://127.0.0.1:3000`, select **Sign in**, and ask how long an
international transfer can remain pending. The browser receives live AI SDK UI
Message Stream v1 events. Stop the server with `Ctrl+C`, then run
`docker compose down` when you no longer need the database.
