Test paired business decisions. Keep the caller signed in and change the
account or action. This proves authorization instead of only proving missing
authentication.

| Valid fixture actor | Action | Expected result |
| --- | --- | --- |
| Alice | Read account A | `200` |
| Bob | Read account A | `200` |
| Bob | Read account C | `403` |
| Dana | Record for account A | `200` |
| Bob | Record for account A | `403` and no repository write |

Use `honoService.app.fetch` in an integration test, with a fresh in-memory
repository per case. Also test logout: the same cookie must return `401` after
the server deletes its session record.

```bash title="Run the authentication and guard tests"
npm test
```

The local session fixture remains intentionally incomplete. It is useful only
because it clearly separates server-established identity from the account/action
decision that the guards enforce.
