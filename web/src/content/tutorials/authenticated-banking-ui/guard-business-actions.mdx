---
title: Guard business actions
description: Add before guards that decide the concrete principal, account, and action permission before a handler can read or write.
order: 34
---

Add `canRead(principalId, accountId)` and `canRecord(principalId, accountId)`
to the injected banking repository. These fixture rules are called mandates:
they connect a valid person, an account, and an allowed action.

Use a before guard on both generated commands:

```ts title="recordTransactionCommandBuilder.ts"
.setBeforeGuardHooks({
  postingAccess: async function (context, payload) {
    if (!context.resources.bankingRepository.canRecord(context.message.principalId, payload.accountId)) {
      throw new HandledError(StatusCode.Forbidden, 'You may not record transactions for this account')
    }
  },
})
```

The list and statement commands use `canRead` with their validated
`parameter.accountId`. The guard runs after schemas validate and before the
handler calls the repository. Bob can read A but cannot read C or post to A,
even though all three requests have valid sessions.

Named guards in the same stage may run concurrently. Do not use two hook names
as an ordered pipeline. The repository must still make an atomic recheck when
a permission or account state can change during a write.
