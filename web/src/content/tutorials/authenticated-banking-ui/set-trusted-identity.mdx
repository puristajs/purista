---
title: Pass trusted identity to PURISTA
description: Set the server-validated principal and tenant in Hono protection middleware before generated endpoints run.
order: 33
---

Generated command endpoints are protected by Hono middleware. Look up the
session cookie first, then set the identity only from that server record:

```ts title="src/http.ts"
honoService.setProtectMiddleware(async (context, next) => {
  const session = findSession(context.req.header('cookie'))
  if (!session) return context.json({ title: 'A local session is required' }, 401)
  context.set('principalId', session.principalId)
  context.set('tenantId', session.tenantId)
  return next()
})
```

Hono runs this middleware for protected generated HTTP endpoints. The command
context now receives trusted `principalId` and `tenantId`. A payload such as
`{ "principalId": "dana" }` must have no effect because caller identity is not
part of the transaction contract.

Test both cases: no cookie gives `401`; a signed-in Bob still reaches the next
business decision. Login only tells the application who sent a request. It
does not grant every account action.
