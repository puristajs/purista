The Hono protection middleware is configured in
`examples/banking/src/index.ts`:

```ts title="examples/banking/src/index.ts"
hono.setProtectMiddleware(async function (context, next) {
  const actor = context.req.header('x-example-actor') ?? 'alice'
  if (!['alice', 'bob', 'carol', 'dana'].includes(actor)) {
    return context.json({ title: 'Unknown example actor' }, 401)
  }
  context.set('principalId', actor)
  context.set('tenantId', 'tenant-north')
  return next()
})
```

Hono runs this middleware for endpoints whose HTTP security is enabled. The
command definitions use the default protected status. The middleware then puts
`principalId` and `tenantId` in the request context that the command guard
receives.

The important boundary is where the values come from. In this local example,
they come from a visible test header and are only safe because the entire
environment is a synthetic fixture. A production middleware must derive them
from a verified credential and must never copy them from a JSON payload or an
unverified client header.

## Test a forged payload cannot choose the actor

The transaction schema has no `principalId` or `tenantId` fields. Even if a
transport ignores an unknown JSON field, the guard reads Bob from middleware,
not an identity value in the payload. The safe rule is: domain payloads
describe a transaction, not the caller.

for the supported Hono protection model.
