---
title: Add the local fixture login
description: Build a deliberately limited server-side session fixture for the browser and terminal examples.
order: 32
---

Add three custom Hono routes in `src/http.ts`: `POST /auth/login`,
`POST /auth/logout`, and `GET /auth/whoami`. Keep a `Map` from a random session
ID to `{ principalId, tenantId }` in the server process. On login, accept only
the documented synthetic actors, set an opaque HttpOnly cookie, and return the
server-held identity.

The key rule is where identity comes from. The browser chooses a fixture name
only for this tutorial route. Protected commands later receive the server's
session record, never an identity taken from a command body or browser header.

Use `curl -c` to save the cookie and `curl -b` to send it:

```bash title="Create and inspect Alice's fixture session"
curl --fail -c .alice-cookie -X POST http://127.0.0.1:3000/auth/login \
  -H 'content-type: application/json' --data '{"actor":"alice"}'
curl --fail -b .alice-cookie http://127.0.0.1:3000/auth/whoami
```

An unknown fixture name must return `400`. In a production application this
route would instead validate a real credential; business guards remain needed
after that change.
