One support case can need more than one kind of analysis. In this chapter, a risk specialist and a response specialist work at the same time. A workflow gives both agents the same case and merges their typed results in a fixed order.

You will learn how to:

- give each agent one clear job and one named model;
- use `fanOut` with explicit call and concurrency limits;
- keep result order stable even when agents finish in a different order;
- protect both the PURISTA command and the mounted workflow;
- invoke the workflow through its three-part PURISTA address; and
- test real parallel execution without calling an external model.

The complete example uses a small support case so the framework behavior stays clear. The tests and local demo use strict fake model providers and need no API key.
