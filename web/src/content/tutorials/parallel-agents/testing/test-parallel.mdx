Bind a separate strict `FakeModelProvider` to each model alias. This avoids a
timing-dependent shared response queue and makes an unexpected specialist call
fail immediately.

```ts title="src/parallelAgents.integration.test.ts"
const riskProvider = new FakeModelProvider({ strict: true })
const responseProvider = new FakeModelProvider({ strict: true })

riskProvider.enqueueObject({
	object: { level: 'high', evidence: ['The customer reports a missing card.'] },
	usage,
	finishReason: 'stop',
})
responseProvider.enqueueObject({
	object: { customerReply: 'We can help secure the card after verification.', nextAction: 'freeze_card' },
	usage,
	finishReason: 'stop',
})
```

Test the PURISTA command separately with `createCommandContextMock`. Inject a
case-policy stub, add trusted identity to the message, resolve only the declared
workflow client, and verify the tenant-scoped session ID.

```ts title="src/service/support/v1/command/analyzeSupportCase/analyzeSupportCaseCommandBuilder.test.ts" write
const { context, stubs } = createCommandContextMock(analyzeSupportCaseCommandBuilder, {
	payload,
	parameter: {},
	resources: { supportCasePolicy: policy },
	sandbox,
})
context.message = getCommandMessageMock({
	tenantId: 'tenant-example',
	principalId: 'principal-alex',
	payload: { payload, parameter: {} },
})
```

Start the mounted Support service on a real `DefaultEventBridge`, invoke the
command with identity, and assert the complete merged output. Also assert each
provider received exactly one request and call `assertExhausted()`.

The successful call crosses both the command guard and mounted-workflow guard.
The denied direct-workflow test returns `false` from
`supportCasePolicy.canAnalyze`, expects a handled `403`, and asserts both
provider request arrays remain empty. That proves business authorization
occurs before either parallel model effect.
