Start in an empty parent directory. This chapter owns a complete project and
does not depend on another tutorial application.

```bash title="Create and enter the parallel-agent project" replay="parent"
npm create purista@2.2.0 parallel-agent-workflow -- --runtime node --event-bridge default --non-interactive --defaults
cd parallel-agent-workflow
```

Replace the generated package manifest. Every `add:*` script calls the
project-local PURISTA CLI. The default demo uses fake model providers.

```json title="package.json" write
{
	"name": "@purista/tutorial-parallel-agents",
	"version": "1.0.0",
	"private": true,
	"type": "module",
	"engines": {
		"node": ">=24.15.0"
	},
	"scripts": {
		"add:service": "purista add service",
		"add:command": "purista add command",
		"add:agent": "purista add agent",
		"add:workflow": "purista add workflow",
		"build": "tsc --noEmit",
		"demo": "node --import tsx src/demo.ts",
		"lint": "biome check .",
		"start": "node --env-file-if-exists=.env --import tsx src/index.ts",
		"test": "vitest run"
	},
	"dependencies": {
		"@purista/core": "4.0.0",
		"@purista/harness": "3.0.0",
		"@purista/harness-openai": "3.0.0",
		"zod": "4.4.3"
	},
	"devDependencies": {
		"@biomejs/biome": "2.5.8",
		"@purista/cli": "4.0.0",
		"@types/node": "26.2.0",
		"@types/sinon": "22.0.0",
		"sinon": "22.1.0",
		"tsx": "4.23.12",
		"typescript": "7.0.2",
		"vitest": "4.1.10"
	}
}
```

Install exactly those dependencies.

```bash title="Install the parallel-agent dependencies" replay="project"
npm install
```

Generate the capability owner, both specialists, their owning workflow, and
the application command that will invoke it.

```bash title="Generate specialists, workflow, and command" replay="project"
npm run add:service -- support --description "Own support cases and support automation" --non-interactive
npm run add:agent -- assess-support-risk --service support --service-version 1 --description "Assess risk in one support case" --non-interactive
npm run add:agent -- plan-support-response --service support --service-version 1 --description "Plan a response for one support case" --non-interactive
npm run add:workflow -- analyze-support-case --service support --service-version 1 --description "Run bounded specialist analysis" --non-interactive
npm run add:command -- analyze-support-case --service support --service-version 1 --description "Run bounded specialist analysis for one support case" --non-interactive
```

The CLI creates one module and colocated test per agent, one workflow module
and test, one service-level `supportHarness.ts`, one mount policy, and the
command files. Keep those generated boundaries; they let one specialist change
without turning the complete Harness into a single large file.

```bash title="Verify the generated parallel workflow checkpoint" replay="project"
npm run build
npm test
```
