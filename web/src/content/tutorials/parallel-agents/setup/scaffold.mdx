Start in an empty parent directory. This chapter creates its own project.

```bash title="Create and enter the project" replay="parent"
npm create purista@3.0.0 parallel-agent-workflow -- --runtime node --event-bridge default --non-interactive --defaults
cd parallel-agent-workflow
```

```bash title="Install the project dependencies" replay="project"
npm install
```

Generate each application boundary once. `--http none` keeps the agents internal. The command has the distinct target `runAnalyzeSupportCase`, so it does not collide with the workflow target `analyzeSupportCase`.

```bash title="Generate the Support boundaries" replay="project"
npm run add:service -- support --description "Own support cases and support automation" --non-interactive
npm run add:agent -- assess-support-risk --service support --service-version 1 --http none --description "Assess risk in one support case" --non-interactive --model-alias riskAssessment
npm run add:agent -- plan-support-response --service support --service-version 1 --http none --description "Plan a response for one support case" --non-interactive --model-alias responsePlanning
npm run add:workflow -- analyze-support-case --service support --service-version 1 --description "Run bounded specialist analysis" --non-interactive
npm run add:command -- run-analyze-support-case --service support --service-version 1 --description "Run bounded specialist analysis for one support case" --non-interactive
```

This chapter supplies focused tests later. Remove the generated placeholder tests now so each final test file is created once.

```bash title="Remove generated placeholder tests" replay="project"
rm src/service/support/v1/harness/agent/assessSupportRisk/assessSupportRiskAgent.test.ts
rm src/service/support/v1/harness/agent/planSupportResponse/planSupportResponseAgent.test.ts
rm src/service/support/v1/harness/workflow/analyzeSupportCase/analyzeSupportCaseWorkflow.test.ts
rm src/service/support/v1/command/runAnalyzeSupportCase/runAnalyzeSupportCaseCommandBuilder.test.ts
```
