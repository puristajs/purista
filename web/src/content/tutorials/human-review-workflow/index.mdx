A support request sometimes needs a person to approve a sensitive action. In
this chapter, the Support service asks to freeze a card. A model proposes the
service-owned tool, Harness pauses with a typed approval interruption, and a
reviewer later approves or rejects that exact run.

```text title="Human-review execution path"
request command
  -> request business guard
  -> typed mounted workflow client
  -> approval-required agent tool
  -> typed tool-approval interruption

decision command
  -> reviewer business guard
  -> resume the same durable run
  -> approved Support host tool
  -> guarded Transaction freeze command, once
```

The interruption is ordinary data. It is not a server error and it is not a
custom browser protocol. The request command returns `waiting` with the run
and approval identifiers that the decision command needs. Harness storage owns
the durable run. The Support review store owns the business request and the
reviewer decision. Transaction owns the card freeze.

Authentication establishes the trusted tenant and principal on the message.
Support guards decide who may request or review a card freeze. Transaction has
its own guard before it changes a card. A prompt and a Skill never make those
decisions.
