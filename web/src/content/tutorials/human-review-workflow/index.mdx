This chapter teaches durable human review as a Framework capability. A PURISTA
command starts a native Harness workflow. The workflow reaches an external
wait, and the command returns an ordinary `waiting` result. A later command
records an authorized decision, signals the wait, and resumes the same run.

The Example Bank fixture asks a reviewer to approve or reject one card freeze.
The business story stays deliberately small so workflow, storage,
authorization, routing, and idempotency remain visible.

```text title="Human review execution path"
request command
  -> business guard
  -> EventBridge workflow address
  -> durable external wait
  -> typed waiting response

decision command
  -> reviewer guard
  -> atomic decision record
  -> signal wait and resume the same run
  -> approved Transaction command, once
```

Harness storage owns workflow checkpoints and the opaque wait. The Support
service database owns review records and reviewer decisions. The Transaction
service owns the protected effect. PURISTA StateStore is not used for these
durable business records.

An external wait differs from approval of one model-selected tool call. Use a
Harness tool-approval interrupt for that AI interaction; its stream can carry
AI SDK UI Message Stream v1 approval parts. This chapter instead teaches an
application workflow with the typed states `waiting`, `approved`, `rejected`,
`expired`, and `cancelled`.
