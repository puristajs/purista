Create a fresh project with published packages. This chapter uses a model to
request approval, so the runtime later needs a model provider and durable
Harness storage.

```bash title="Create and enter the project" replay="parent"
npm create purista@3.0.0 human-review-workflow -- --runtime node --event-bridge default --non-interactive --defaults
cd human-review-workflow
```

Replace the package manifest with the project contract used by the examples.

```json title="package.json" write
{
	"name": "@purista/tutorial-human-review-workflow",

```
```bash title="Install and generate the project boundaries" replay="project"
npm install
npm run add:service -- support --description "Owns support reviews and automation" --non-interactive
npm run add:service -- transaction --description "Owns transaction and card actions" --non-interactive
npm run add:workflow -- review-support-action --service support --service-version 1 --description "Request a human approval for a card freeze" --non-interactive
npm run add:agent -- review-support-approval-agent --service support --service-version 1 --http none --description "Request an approval before a card freeze" --non-interactive --model-alias review
npm run add:tool -- freeze-reviewed-card --service support --service-version 1 --kind purista --description "Freeze an approved card" --non-interactive
npm run add:command -- request-card-freeze --service support --service-version 1 --description "Request a card-freeze review" --non-interactive
npm run add:command -- decide-card-freeze --service support --service-version 1 --description "Record a review decision" --non-interactive
npm run add:command -- freeze-card --service transaction --service-version 1 --description "Freeze a card after an approved review" --non-interactive
rm src/service/support/v1/harness/workflow/reviewSupportAction/reviewSupportActionWorkflow.test.ts
rm src/service/support/v1/harness/agent/reviewSupportApprovalAgent/reviewSupportApprovalAgent.test.ts
rm src/service/support/v1/harness/tool/freezeReviewedCard/freezeReviewedCardTool.test.ts
rm src/service/support/v1/command/requestCardFreeze/requestCardFreezeCommandBuilder.test.ts
rm src/service/support/v1/command/decideCardFreeze/decideCardFreezeCommandBuilder.test.ts
rm src/service/transaction/v1/command/freezeCard/freezeCardCommandBuilder.test.ts
```

The final `rm` commands remove the generated starter tests. The testing pages
add focused command and integration tests after the behavior is complete.

All Harness definitions belong beneath `src/service/support/v1/harness/`.
The Support service mounts one workflow root. The Transaction service keeps the
actual card-change command.

```bash title="Check the generated project" replay="project"
npm run build
```
