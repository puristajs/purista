Create a fresh project and install the published Framework and Harness
packages. This workflow does not call a model, so it needs no provider adapter
or API key.

```bash title="Create the human-review project" replay="project"
npm create purista@latest human-review-workflow
cd human-review-workflow
npm install --save-exact @purista/core@4.0.0 @purista/harness@3.0.0 zod@4.4.3
npm install --save-dev --save-exact @purista/cli@4.0.0 @types/node@26.2.0 @types/sinon@22.0.0 sinon@22.1.0 tsx@4.23.12 typescript@7.0.2 vitest@4.1.10
```

Add project-local scripts for each generated artifact.

```json title="package.json" add={7-9}
{
	"scripts": {
		"add:service": "purista add service",
		"add:command": "purista add command",
		"add:workflow": "purista add workflow",
		"build": "tsc --noEmit",
		"demo": "node --import tsx src/demo.ts",
		"lint": "biome check .",
		"start": "node --import tsx src/index.ts",
		"test": "vitest run"
	}
}
```

Generate the two capability owners, then let the PURISTA CLI create the native
workflow module, service-level Harness composition, mount policy, and service
registration.

```bash title="Generate the services and workflow" replay="project"
npm run add:service -- support --description "Owns support reviews and automation" --non-interactive
npm run add:service -- transaction --description "Owns transaction and card actions" --non-interactive
npm run add:workflow -- review-support-action --service support --service-version 1 --description "Wait for an authorized support review decision" --non-interactive
```

Replace the generated workflow body with a versioned external wait. The input
contains opaque workflow identity and integrity fields. Mutable review data,
comments, and user profiles belong in the Support database.

```ts title="src/harness/support/workflow/reviewSupportAction/reviewSupportActionWorkflow.ts" write
export const reviewSupportActionWorkflow = defineHarnessModule()('support.workflow.review-support-action', {
	version: '1.0.0',
	register(builder) {
		return builder.workflow('review_support_action', {
			input: reviewSupportActionInputSchema,
			output: reviewSupportActionOutputSchema,
			handler: async (context) => {
				const outcome = await context.externalWait.wait({
					waitId: context.input.waitId,
					kind: 'human_review',
					schemaVersion: 'support-review-signal-v1',
					definitionVersion: context.input.definitionVersion,
					deadline: context.input.deadline,
				})
				return { status: outcome.status }
			},
		})
	},
})
```

Compose the module once for the Support service.

```ts title="src/harness/support/supportHarness.ts" write
import { defineHarness } from '@purista/harness'
import { reviewSupportActionWorkflow } from './workflow/reviewSupportAction/reviewSupportActionWorkflow.js'

export const supportHarness = defineHarness({ name: 'support-human-review' })
	.use(reviewSupportActionWorkflow)
	.define()
```

The workflow address is directly callable, so its mount policy must authorize
the current principal. The guard loads the tenant-scoped review by wait ID,
checks its immutable action digest, and then applies either requester or
reviewer business policy.

```ts title="src/service/support/v1/harness/supportHarnessMount.ts" write
export const supportHarnessPolicy = {
	publish: { agents: [], workflows: ['review_support_action'] },
	targets: {
		agents: {},
		workflows: {
			review_support_action: {
				beforeGuards: {
					reviewAccess: async (
						context: HarnessBusinessGuardContext<{
							supportReviewPolicy: SupportReviewPolicy
							supportReviewStore: SupportReviewStore
						}>,
						input: Parameters<typeof requireReviewWorkflowAccess>[2],
					) => {
						await requireReviewWorkflowAccess(context.resources, context.identity, input)
					},
				},
				durableResume: { identity: 'run-owner' },
			},
		},
	},
} as const
```

`durableResume.identity: 'run-owner'` is an explicit cross-principal review
policy. An authorized reviewer may reopen the run created by the requester.
PURISTA still evaluates the guard with the current reviewer and always rejects
a different tenant. The caller must also supply the original session ID,
durable run ID, and workflow input.
