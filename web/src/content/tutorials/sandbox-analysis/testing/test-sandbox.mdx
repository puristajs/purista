Start with the native Harness definition. Bind `localDirectorySandbox` with an
explicit `python3` allowlist and a strict fake model. This fast test exercises
the same built-in tool loop without requiring a Docker daemon. The adapter
restricts files to the temporary test root, but its optional executor runs an
allowlisted host process. It proves tool wiring and permission handling, not
container isolation.

Script four strict model rounds:

1. call `write` for `/workspace/transactions.csv`;
2. call `bash` with the allowed `python3` command;
3. call `read` for `/workspace/summary.json`;
4. return the final structured analysis.

```ts title="src/harness/analysis/transactionAnalysisHarness.test.ts"
sandbox: localDirectorySandbox({
	root,
	exec: { allowCommands: ['python3'], timeoutMs: 5_000 },
})
```

Add a second native test where the model tries to write `/outside.txt`. Harness
returns a standard `PERMISSION_DENIED` tool result to the model, allowing it to
recover. Inspect that tool message instead of expecting the entire agent run to
become an exception.

Test the command separately with `createCommandContextMock`. Inject a policy
resource, set the trusted tenant and principal on the message, and assert the
exact caller-scoped session passed to the declared agent client.

Then invoke the command over `DefaultEventBridge`, assert the structured output,
and inspect the first provider request. The model tool surface must be exactly
`bash`, `read`, and `write`. The successful path crosses both business guards;
the direct-agent denial test proves no model request occurs when authorization
fails.

```ts title="src/sandboxAnalysis.integration.test.ts"
const firstRequest = provider.requests[0]
expect(
	firstRequest && 'tools' in firstRequest
		? firstRequest.tools?.map(tool => tool.name).sort()
		: [],
).toEqual(['bash', 'read', 'write'])
provider.assertExhausted()
```

The opt-in Docker integration binds the same scripted model to `dockerSandbox`.
It runs the Python tool call in the prepared non-root image, then purges the
tenant's exact sandbox resources before deleting the private adapter journal.

```bash title="Verify the sandbox chapter" replay="project"
npm run build
npm test
npm run lint
npm run demo
```

The retained tests and demo pass without Docker or an API key. The demo crosses
the real PURISTA EventBridge and mounted Harness boundary with the local test
adapter and labels no output as container-isolated. This chapter remains a
draft until the released PURISTA v4 and Harness v3 packages pass a clean
registry replay.

After building the pinned sandbox image in the configuration lesson, copy the
environment template, set its immutable image id, and start the Analysis
service.

```bash title="Run the sandbox analysis service" replay="project"
cp .env.example .env
npm run test:docker
npm start
```
