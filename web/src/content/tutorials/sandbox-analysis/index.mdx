This chapter teaches isolated agent execution. A transaction-analysis agent
writes an input file, runs a small Python program, reads the result, and
returns a structured recommendation. It cannot access the application host
filesystem or execute arbitrary commands.

The analysis is advisory. A separate guarded PURISTA command would own any
business effect such as blocking a transaction.

You will learn how to:

- configure the Docker sandbox adapter at the composition root;
- expose only the `write`, `bash`, and `read` built-in tools;
- restrict writes and executable commands;
- protect the agent behind a business guard;
- test tool calls without a Docker daemon;
- retain and purge sandbox resources deliberately.

1. [Configure an isolated sandbox](./build/configure/)
2. [Run only the required tools](./build/run-tool/)
3. [Release and purge sandbox resources](./build/cleanup/)
4. [Test the complete tool loop](./testing/test-sandbox/)

The retained project is in `examples/banking/chapters/sandbox-analysis` and
includes a Dockerfile and Compose build target.
