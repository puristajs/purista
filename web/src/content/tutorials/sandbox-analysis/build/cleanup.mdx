`service.destroy()` shuts down the mounted Harness and releases live
attachments. It does not silently delete persistent sandbox data that a later
session may need. Deletion is an application retention decision.

Keep the adapter instance returned by the composition root. Call its
administration methods only from a trusted operator path protected by PURISTA
authentication and business authorization. Never expose this surface directly
to a model or public route.

For example, a tenant offboarding command can purge the exact tenant selector:

```ts title="Trusted retention operation"
const result = await sandbox.administration.purge({
	selector: {
		kind: 'tenant',
		namespace: 'transaction-analysis',
		tenantId,
	},
	idempotencyKey: `analysis-purge:${tenantId}:${retentionJobId}`,
	limit: 100,
})
```

Handle both truthful results:

- `completed` means no selected resources remain;
- `cleanup_pending` includes `retryAfterMs` and must be retried with the same
  private metadata and idempotency key.

Do not delete the adapter metadata directory after a cleanup failure. It holds
the ownership journal required to retry the exact provider effects safely.

For routine retention, run bounded `administration.sweep` calls from a
scheduled PURISTA job and continue with `nextCursor`. Keep the scheduler,
operator policy, and audit events in application code.
