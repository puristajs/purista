Retrieval-augmented generation, usually shortened to RAG, gives a model
relevant application data before it writes an answer. A complete RAG feature
has two connected paths: an indexing path that prepares source documents and
an answer path that retrieves evidence for each question.

This chapter builds both paths. PURISTA owns the service boundaries,
authorization, HTTP endpoints, database resource, and address-first calls.
The native Harness owns the embedding and chat model contracts, the retrieval
agent, its tool contract, and the answer workflow.

```text title="The complete RAG path"
protected ingestion command
  -> collection edit guard
  -> chunk source text
  -> Harness embedding model
  -> PostgreSQL and pgvector resource

protected chat stream
  -> mounted Harness workflow
  -> retrieval agent chooses search_knowledge
  -> authorized PURISTA search command
  -> same Harness embedding model
  -> pgvector similarity search
  -> grounded answer with citations
  -> AI SDK UI Message Stream v1
```

The small Example Bank source document makes the result easy to try. The
lesson is about building RAG with PURISTA; it does not introduce a banking
domain model.

## What you will build

You will:

1. create a PURISTA project and install the published Framework, Harness,
   OpenAI adapter, Hono, and AI SDK UI adapter packages;
2. define one Harness with a chat model and an embedding model;
3. build a protected command that chunks, embeds, and stores a reviewed source;
4. build a protected search command that embeds the question with the same
   model contract;
5. expose that search command as a typed host tool;
6. let a Harness agent choose the tool and stream a grounded answer;
7. authenticate browser requests with an Identity service and StateStore-backed sessions;
8. connect a standard React and AI Elements UI; and
9. test models, resources, authorization, tool choice, and stream events
   without calling a paid provider.

The complete source is in `examples/banking/chapters/retrieval-ingestion`.
This chapter stays a draft until PURISTA v4 and Harness v3 are available from
npm and a clean consumer replay succeeds.
