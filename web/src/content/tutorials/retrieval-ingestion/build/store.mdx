Knowledge documents and embeddings are durable business records. They belong
in a database resource. PURISTA StateStore remains available for session-like
application state and is not used as a document database.

Declare repository operations on the service builder. Handlers depend on this
business interface rather than `pg`, SQL, or a connection pool.

```ts title="src/service/knowledge/v1/knowledgeV1ServiceBuilder.ts"
export const knowledgeV1ServiceBuilder = new ServiceBuilder(knowledgeServiceInfo)
	.setConfigSchema(
		z.object({
			embeddingModel: z.string().min(1),
			embeddingDimensions: z.number().int().positive(),
		}),
	)
	.defineResource<'knowledgeCollectionPolicy', KnowledgeCollectionPolicy>()
	.defineResource<'knowledgeRepository', KnowledgeRepository>()
```

The command passes the trusted tenant id, the embedding model id, and the
validated vectors to the resource. The repository replaces the document row
and all of its chunks in one transaction. A failed insert therefore cannot
leave a document with half of its new chunks.

```ts title="src/service/knowledge/v1/command/ingestKnowledge/ingestKnowledgeCommandBuilder.ts"
		await context.resources.knowledgeRepository.replaceRevision(
			{
				tenantId: context.message.tenantId ?? '',
				collectionId: payload.collectionId,
				documentId: payload.documentId,
				revision: payload.revision,
				title: payload.title,
				embeddingModel: this.config.embeddingModel,
				chunks: chunks.map((content, index) => {
					const embedding = embeddings[index]
					if (!embedding) throw new Error('The embedding model omitted a document vector')
					return { index, content, embedding: [...embedding.vector] }
				}),
			},
			signal,
		)
```

The Compose file starts PostgreSQL with pgvector and initializes two scoped
tables. `knowledge_documents` owns the current revision. `knowledge_chunks`
stores the text and its vector. The database starts empty because the tutorial
UI exercises the real ingestion endpoint before chat.

```yaml title="compose.yaml"
services:
  postgres:
    image: pgvector/pgvector:0.8.1-pg16
    environment:
      POSTGRES_DB: example_bank
      POSTGRES_USER: example_bank
      POSTGRES_PASSWORD: local-example-password
```
