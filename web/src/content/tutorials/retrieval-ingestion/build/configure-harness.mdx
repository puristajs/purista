Start in an empty parent directory. `npm create purista` creates the application
folder; every later command on this page runs inside that folder.

```bash title="Create and enter the RAG project" replay="parent"
npm create purista@2.2.0 example-rag -- --runtime node --event-bridge default --non-interactive --defaults
cd example-rag
```

Install that manifest exactly as a normal consumer would.

```bash title="Install the published RAG application dependencies" replay="project"
npm install
```

Generate every Framework and Harness boundary before editing it. The agent and
workflow commands create colocated modules and tests below
`src/harness/knowledge`. Keep those generated locations. Later steps replace
the placeholder implementations inside them.

```bash title="Generate the Knowledge boundaries" replay="project"
npm run add:service -- knowledge --description "Own knowledge sources, retrieval, and grounded answers" --non-interactive
npm run add:command -- ingest-knowledge --service knowledge --service-version 1 --description "Chunk, embed, and store one reviewed knowledge revision" --non-interactive
npm run add:command -- search-knowledge --service knowledge --service-version 1 --description "Search authorized knowledge chunks" --non-interactive
npm run add:stream -- answer-knowledge-question --service knowledge --service-version 1 --description "Stream a grounded answer" --non-interactive
npm run add:agent -- retrieve-evidence --service knowledge --service-version 1 --description "Retrieve evidence for a grounded answer" --non-interactive
npm run add:workflow -- answer-knowledge-question --service knowledge --service-version 1 --description "Retrieve evidence and stream a grounded answer" --non-interactive
npm run add:service -- identity --description "Own local tutorial sessions" --non-interactive
npm run add:command -- login --service identity --service-version 1 --description "Create a local tutorial session" --non-interactive
npm run add:command -- resolve-session --service identity --service-version 1 --description "Resolve a local tutorial session" --non-interactive
```

Create one shared schema file. These contracts connect commands, the native
tool, the agent, the workflow, and the browser stream. A schema validates data
at runtime and also gives TypeScript its inferred type.

```ts title="src/service/knowledge/v1/schema.ts" write
import { z } from 'zod'

export const ingestKnowledgeInputSchema = z.object({
	collectionId: z.string().min(1).max(64),
	documentId: z.string().min(1).max(80),
	revision: z.number().int().positive(),
	title: z.string().min(1).max(120),
	content: z.string().min(1).max(20_000),
})

export const ingestKnowledgeOutputSchema = z.object({
	documentId: z.string().min(1),
	revision: z.number().int().positive(),
	chunkCount: z.number().int().positive(),
	embeddingModel: z.string().min(1),
})

export const knowledgeMatchSchema = z.object({
	documentId: z.string().min(1),
	chunkIndex: z.number().int().nonnegative(),
	content: z.string().min(1),
	score: z.number().min(0).max(1),
})

export const searchKnowledgeInputSchema = z.object({
	collectionId: z.string().min(1),
	query: z.string().min(1).max(2_000),
	limit: z.number().int().min(1).max(8).default(4),
})

export const searchKnowledgeOutputSchema = z.object({
	matches: z.array(knowledgeMatchSchema).max(8),
})

export const answerKnowledgeQuestionInputSchema = z.object({
	collectionId: z.string().min(1),
	question: z.string().min(1).max(2_000),
})

export const retrievedEvidenceSchema = z.object({
	question: z.string().min(1),
	evidence: z.array(knowledgeMatchSchema).min(1).max(8),
})

export const aiSdkTextPartSchema = z
	.object({
		type: z.literal('text'),
		text: z.string(),
	})
	.passthrough()

export const aiSdkMessageSchema = z
	.object({
		id: z.string().min(1).optional(),
		role: z.enum(['system', 'user', 'assistant']),
		parts: z.array(z.unknown()),
	})
	.passthrough()

export const answerKnowledgeQuestionHttpInputSchema = z.object({
	id: z.string().min(1),
	messages: z.array(aiSdkMessageSchema).min(1),
	collectionId: z.string().min(1).default('customer-help'),
})

export const aiSdkUiMessageSseEventSchema = z.object({
	event: z.literal('data'),
	data: z.unknown(),
})

export const answerKnowledgeQuestionFinalSchema = z.object({
	status: z.literal('completed'),
})

export type SearchKnowledgeInput = z.input<typeof searchKnowledgeInputSchema>
export type KnowledgeMatch = z.output<typeof knowledgeMatchSchema>
```
The schemas are now the shared language for both sides of RAG. The next pages
build the indexing command first. The retrieval page later fills the generated
agent and workflow modules, then composes them in one small Harness definition.
