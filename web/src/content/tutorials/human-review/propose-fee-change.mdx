Dana starts a proposal with `POST /api/v1/fee-changes`. The example accepts
an account ID, an integer minor-unit fee, a reviewer, and an ISO-8601 expiry
time. The repository creates a proposal ID, stores the current fee as the
expected value, and sets `version: 1` and `status: 'pending'`.

```ts title="examples/banking/src/review/service.ts"
const requireFeeChangeProposer = (context: ReviewContext, accountId: 'account-a' | 'account-c') => {
  const actor = requireActor(context)
  if (actor !== 'dana' || accountId !== 'account-a') {
    throw new HandledError(StatusCode.Forbidden, 'Only synthetic operations may propose account-a fee changes')
  }
  return actor
}
```

This is an application-owned business decision. It does more than check that
an actor exists: Dana may propose only for the teaching account, may not name
themself as reviewer, and may select only a reviewer assigned to that account.

The current source does not use an AI agent to generate a proposal. A caller
provides the typed data directly. The stored proposal is an input to human
review, not evidence that a fee should change.
