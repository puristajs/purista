---
title: Record a reviewer decision
description: Approve or reject only the pending, current, unexpired proposal revision.
order: 164
status: published
---

The reviewer calls:

```text title="Generated local route"
POST /api/v1/fee-changes/:proposalId/decisions
```

The body contains `expectedVersion` and either `approved` or `rejected`.
The store rejects a stale version, a second decision, or an expired proposal.
An approval records both `approvedVersion` and `decisionBy`. A rejection
records the reviewer and prevents application.

If Dana revises the proposal, the store increments the version and returns it
to `pending`. The older approval no longer applies. This prevents someone
from approving one amount while another amount is later applied.

There is no durable workflow wait in this checkpoint. A pending proposal is
only an in-memory record, and no HTTP request remains open while the reviewer
decides. Restart recovery, notifications, review history, and a browser
reviewer screen require additional implementation.
