Different actions have different business rules:

| Action | Allowed actor in this fixture | Important rejection |
| --- | --- | --- |
| Propose or revise account A | Dana | Dana cannot be the reviewer. |
| Decide a proposal | Its assigned reviewer, Erin | Dana and unassigned Bob receive `403`. |
| Apply an approval | The original proposer, Dana | Another actor cannot apply it. |

The decision guard reads the stored proposal. It checks that the caller is the
assigned reviewer, is not the proposer, and is assigned to the proposal's
account by `BankingRepository.canReviewCase()`.

```ts title="examples/banking/src/review/service.ts"
if (actor !== proposal.reviewerId) {
  throw new HandledError(StatusCode.Forbidden, 'This fee change is assigned to a different reviewer')
}
if (actor === proposal.proposedBy) {
  throw new HandledError(StatusCode.Forbidden, 'A proposer cannot approve their own fee change')
}
```

These guards are not a replacement for state checks in the store. The store
also verifies the proposal's version, state, expiry, and expected current fee
at the point where it writes the effect.
