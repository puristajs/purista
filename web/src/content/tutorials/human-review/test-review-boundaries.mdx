Run the integration test:

```bash title="Verify the human-review checkpoint"
npm run test -w @purista/banking-tutorials
```

The test starts the real PURISTA service and Hono routes. It proves that:

- applying a pending proposal returns `409` and leaves the fee unchanged;
- Dana cannot approve their own proposal, and unassigned Bob receives `403`;
- assigned reviewer Erin can approve the current proposal;
- a rejected proposal cannot be applied;
- revising a proposal invalidates its earlier approval and rejects the stale
  apply request;
- expiry returns `410` without changing the fee; and
- the first valid apply changes the fee once while a replay returns `409`.

This proof includes main-app local-session integration but not a browser
fee-review screen, durable review state, scheduled expiry processing, a
model, or a real payment system. Treat `x-test-actor` in the focused service
test as test wiring only; it is never a client authentication mechanism.

Next, extend the application only after adding real session composition and
the corresponding end-to-end tests.
