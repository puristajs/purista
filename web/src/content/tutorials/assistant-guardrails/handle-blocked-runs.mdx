---
title: Understand a blocked run
description: Explain what a native Harness decision block proves and what this small fixture does not prove.
order: 135
status: published
---

When an interceptor returns `{ decision: 'block' }`, Harness records a
content-free `DECISION_BLOCKED` outcome. The client receives a failure
response; the example intentionally does not reflect the marker or unsafe
tool text back to the caller.

The test covers three failure stages:

1. unsafe input: no provider request;
2. unsafe tool result: no second provider request;
3. unsafe final output: no response body containing the candidate answer.

The fixture does not classify real secrets, detect all malicious instructions,
measure false positives, or offer a human-friendly refusal UI. Treat a
detector timeout or implementation error as a failed check until a separately
tested policy says otherwise. Add a real detector only with its provider,
latency, privacy, error, and evaluation evidence.
