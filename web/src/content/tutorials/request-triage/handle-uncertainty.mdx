---
title: Handle low confidence and review
description: Return a safe no-action result when the model asks for review, is uncertain, or chooses an unsupported category.
order: 105
---

Classification is not an authorization decision. The agent first checks that
the caller may read the selected account. Only then does it put the customer
text into a model request. A category cannot grant access to another account.

The current routing policy returns `no-action` when `needsReview` is true, when
confidence is below `0.8`, or when the category is `other`. The focused test
uses a `card-payment` answer with confidence `0.4` and asserts this result:

```ts title="Expected low-confidence response from the test"
{
  category: 'card-payment',
  routing: { status: 'no-action', reason: 'low-confidence' }
}
```

The output schema rejects invalid categories, empty reasons, a missing review
flag, or a confidence outside zero through one. The current test does not add
an instruction-injection fixture, timeout case, persistence layer, or human
review queue. Do not claim those controls from this isolated proof.
