Open the generated `schema.ts`. A queue payload crosses an asynchronous
boundary, so make its data explicit. The browser is allowed to ask for an
`accountId`; the server adds the verified requester before it enqueues the
job. The worker later uses that server-owned value for a new business check.

```ts title="src/service/bankingOperations/v1/queue/generateStatement/schema.ts"
import { extendApi } from '@purista/core'
import { z } from 'zod'

export const bankingOperationsV1GenerateStatementQueuePayloadSchema = extendApi(
  z.object({
    accountId: z.string().min(1),
    initiatorPrincipalId: z.enum(['alice', 'bob', 'carol', 'dana', 'erin']),
  }),
  { title: 'statement generation job' },
)

export const bankingOperationsV1GenerateStatementQueueParameterSchema = extendApi(
  z.object({ tenantId: z.literal('tenant-north') }),
  { title: 'statement generation scope' },
)
```

The parameter is not trusted browser input. The command supplies the tenant
after server-side authentication. Keeping it in the queue contract makes the
scope visible to both the producer and worker.

## Set the queue lifecycle

The generated queue builder already imports both schemas. Add a small retry
budget and a lease duration that suits this training job.

```ts title="src/service/bankingOperations/v1/queue/generateStatement/generateStatementQueueBuilder.ts"
export const generateStatementQueueBuilder = bankingOperationsV1ServiceBuilder
  .getQueueBuilder('generateStatement', 'Generate statement metadata for one authorized account')
  .addPayloadSchema(bankingOperationsV1GenerateStatementQueuePayloadSchema)
  .addParameterSchema(bankingOperationsV1GenerateStatementQueueParameterSchema)
  .setLifecycleConfig({
    maxAttempts: 3,
    visibilityTimeoutMs: 30_000,
  })
```

`maxAttempts` is the retry budget a queue bridge may use. `visibilityTimeoutMs`
is the worker lease length. Neither setting makes the local in-memory bridge
durable. Use a real queue adapter and integration tests before depending on
restart recovery.

## Add a direct contract test

Keep the generated definition test and add one assertion for the final queue
identifier. This catches a mismatch between the producer's `canEnqueue` call
and the queue it is meant to reach.

```ts title="src/service/bankingOperations/v1/queue/generateStatement/generateStatementQueueBuilder.test.ts"
import { describe, expect, it } from 'vitest'

import { generateStatementQueueBuilder } from './generateStatementQueueBuilder.js'

describe('generateStatement queue', () => {
  it('defines the statement queue contract', async () => {
    const definition = await generateStatementQueueBuilder.getDefinition()
    expect(definition.queueName).toBe('generateStatement')
  })
})
```

```bash title="Test the typed queue definition"
npm test -- --run src/service/bankingOperations/v1/queue/generateStatement/generateStatementQueueBuilder.test.ts
```
