Use a stream when one connected caller needs short-lived progress. Use a queue
when the caller only needs a reference and the work has its own lifecycle. A
statement request is the second case: the API returns a job ID while a worker
does the later work.

## Generate the queue

The CLI creates the queue and its first worker together. This prevents a
queue contract from being added without a consumer. The statement command is
already part of the banking API, so disable the optional generated producer
command and connect that existing command in the next step.

```bash title="Generate the statement queue and its primary worker"
npm run add:queue -- generate-statement \
  --description "Generate statement metadata for one authorized account" \
  --service banking-operations \
  --service-version 1 \
  --worker-name generate-statement-worker \
  --worker-description "Build statement metadata for an authorized account" \
  --worker-mode continuous \
  --max-parallel-handlers 1 \
  --without-producer
```

For the default camel-case project convention, this writes and wires these
files. Your `purista.json` controls the exact casing and service path, so use
those settings when your project differs.

```text title="Files generated by add:queue"
src/service/bankingOperations/v1/queue/generateStatement/schema.ts
src/service/bankingOperations/v1/queue/generateStatement/types.ts
src/service/bankingOperations/v1/queue/generateStatement/generateStatementQueueBuilder.ts
src/service/bankingOperations/v1/queue/generateStatement/generateStatementQueueBuilder.test.ts
src/service/bankingOperations/v1/queue-worker/generateStatementWorker/generateStatementWorkerQueueWorkerBuilder.ts
src/service/bankingOperations/v1/queue-worker/generateStatementWorker/generateStatementWorkerQueueWorkerBuilder.test.ts
```

The CLI also adds both definitions to the generated service composition file.
Do not hand-add a second import or a second definition entry.

## Check the generated starting point

Run the test that came with the worker before changing it. It proves that the
worker definition can be resolved through the service runtime. Then run the
project typecheck.

```bash title="Verify the generated queue before editing it"
npm test -- --run src/service/bankingOperations/v1/queue-worker/generateStatementWorker/generateStatementWorkerQueueWorkerBuilder.test.ts
npm run typecheck
```

The generated schemas intentionally accept `unknown` payload data and an empty
parameter object. They are a safe scaffold, not a banking contract. Replace
them next.

The reference implementation keeps this chapter's final code together in
`examples/banking/src/advanced/service.ts`, where the queue is named
`banking.generateStatement` to make its application-wide purpose clear.
