Open the worker generated by `add:queue`. Its starter handler only completes a
job. Replace that stub with the smallest useful business result: statement
metadata containing a transaction count and generation time.

## Repeat the current business decision

A worker runs later than the HTTP request. The caller may have lost account
access during that time, so it repeats the account-read rule using the
server-owned requester in the queue payload. This is a business guard; it is
not a second login check.

```ts title="src/service/bankingOperations/v1/queue-worker/generateStatementWorker/generateStatementWorkerQueueWorkerBuilder.ts"
export const generateStatementWorkerQueueWorkerBuilder = bankingOperationsV1ServiceBuilder
  .getQueueWorkerBuilder('generateStatement', 'Build statement metadata for an authorized account')
  .setMode('continuous')
  .setMaxParallelHandlers(1)
  .setBeforeGuardHooks({
    currentInitiatorAccountRead: async function (context, message) {
      if (
        !context.resources.bankingRepository.canRead(
          message.payload.initiatorPrincipalId,
          message.payload.accountId,
        )
      ) {
        throw new HandledError(StatusCode.Forbidden, 'The statement requester may no longer read this account')
      }
    },
  })
```

## Write the projection and acknowledge the job

The worker receives the typed payload from the queue builder. It reads the
banking repository, writes a small projection through an injected store, and
acknowledges success with `context.job.complete(...)`.

```ts title="src/service/bankingOperations/v1/queue-worker/generateStatementWorker/generateStatementWorkerQueueWorkerBuilder.ts"
  .setHandler(async function (context) {
    const { accountId } = context.message.payload
    const transactionCount = context.resources.bankingRepository.list(accountId).length
    const statement = context.resources.operationsStore.saveStatement({
      statementId: `statement-${accountId}`,
      accountId,
      transactionCount,
      generatedAt: new Date().toISOString(),
    })

    await context.job.complete({
      statementId: statement.statementId,
      accountId: statement.accountId,
      transactionCount,
    })
    return { status: 'success' as const }
  })
```

The example stores metadata only. It does not create a PDF, retain file bytes,
or expose a download. The completed implementation is
`generateStatementWorker` in `examples/banking/src/advanced/service.ts`.

## Test one job directly

Replace the generated smoke test with a focused handler test. A queue-worker
context mock gives the handler typed payload, parameters, resources, and a job
completion spy without starting a long-running worker.

```ts title="src/service/bankingOperations/v1/queue-worker/generateStatementWorker/generateStatementWorkerQueueWorkerBuilder.test.ts"
it('writes statement metadata and acknowledges an authorized job', async () => {
  const mock = createQueueWorkerContextMock(generateStatementWorkerQueueWorkerBuilder, {
    queueName: 'generateStatement',
    payload: { accountId: 'account-a', initiatorPrincipalId: 'alice' },
    parameter: { tenantId: 'tenant-north' },
    resources: createResources(),
  })
  const definition = await generateStatementWorkerQueueWorkerBuilder.getDefinition()

  await definition.handler(mock.context, mock.message)

  expect(mock.stubs.job.complete.calledOnce).toBe(true)
  expect(mock.context.resources.operationsStore.getStatement('account-a')).toMatchObject({
    statementId: 'statement-account-a',
    transactionCount: 1,
  })
})
```

```bash title="Run the worker test"
npm test -- --run src/service/bankingOperations/v1/queue-worker/generateStatementWorker/generateStatementWorkerQueueWorkerBuilder.test.ts
```
