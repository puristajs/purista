description: Extend the generated command with a business guard and typed queue capability, then return only the job reference.

The queue does not expose an HTTP endpoint itself. A command owns the request
boundary. Add this work to the existing `requestStatementGeneration` command
created with `npm run add:command` in the transaction API chapter.

## Declare the queue capability

Import the queue schemas from the files created in the last step. Then declare
the exact queue the command may use with `.canEnqueue(...)`. That declaration
creates the typed `context.queue.enqueue.generateStatement` helper.

```ts title="src/service/bankingOperations/v1/command/requestStatementGeneration/requestStatementGenerationCommandBuilder.ts"
export const requestStatementGenerationCommandBuilder = bankingOperationsV1ServiceBuilder
  .getCommandBuilder('requestStatementGeneration', 'Queue a statement for the current account reader')
  .addPayloadSchema(z.object({ accountId: z.string().min(1) }))
  .addParameterSchema(z.object({}))
  .addOutputSchema(z.object({ jobId: z.string(), queueName: z.literal('generateStatement') }))
  .canEnqueue(
    'generateStatement',
    bankingOperationsV1GenerateStatementQueuePayloadSchema,
    bankingOperationsV1GenerateStatementQueueParameterSchema,
  )
```

## Check the business action, then enqueue

Authentication establishes who the caller is. This guard answers a different
question: may that known caller read this particular account now? The command
adds `initiatorPrincipalId` itself. Never accept this field from the request
body, because a caller could impersonate a more privileged account reader.

```ts title="src/service/bankingOperations/v1/command/requestStatementGeneration/requestStatementGenerationCommandBuilder.ts"
  .setBeforeGuardHooks({
    accountRead: async function (context, payload) {
      if (!context.resources.bankingRepository.canRead(context.message.principalId, payload.accountId)) {
        throw new HandledError(StatusCode.Forbidden, 'You may not read this account')
      }
    },
  })
  .setCommandFunction(async function (context, payload) {
    const initiatorPrincipalId = context.message.principalId
    if (!initiatorPrincipalId || !isExampleActor(initiatorPrincipalId)) {
      throw new HandledError(StatusCode.Unauthorized, 'A verified statement requester is required')
    }

    const job = await context.queue.enqueue.generateStatement(
      { ...payload, initiatorPrincipalId },
      { tenantId: 'tenant-north' },
      { idempotencyKey: `statement:${initiatorPrincipalId}:${payload.accountId}` },
    )
    return { jobId: job.jobId, queueName: 'generateStatement' }
  })
```

Expose it as `POST /statements/generate` only after the command works in a
direct test. The reference banking app uses the same boundary with its
application-wide queue name in
`examples/banking/src/advanced/service.ts`.

## Test the producer boundary

Use a command-context mock. The test proves the guard-compatible command asks
the declared queue to accept a server-owned requester and returns a reference;
it does not claim that a worker has already finished.

```ts title="src/service/bankingOperations/v1/command/requestStatementGeneration/requestStatementGenerationCommandBuilder.test.ts"
it('returns the queue reference for an authorized account reader', async () => {
  const mock = createCommandContextMock(requestStatementGenerationCommandBuilder, {
    payload: { accountId: 'account-a' },
    parameter: {},
    resources: createResources(),
  })
  mock.stubs.enqueue.resolves({ jobId: 'job-statement-1', queueName: 'generateStatement' })
  mock.context.message.principalId = 'alice'

  await expect(
    requestStatementGenerationCommandBuilder
      .getCommandFunction()
      .call({} as never, mock.context, { accountId: 'account-a' }, {}),
  ).resolves.toEqual({ jobId: 'job-statement-1', queueName: 'generateStatement' })
})
```

```bash title="Run the producer-command test"
npm test -- --run src/service/bankingOperations/v1/command/requestStatementGeneration/requestStatementGenerationCommandBuilder.test.ts
```
