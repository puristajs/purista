description: Guard the request and return the queue reference without pretending that the statement is already ready.

The command exposes `POST /api/v1/statements/generate`. It lets an authorized
reader request generation for their account.

```ts title="examples/banking/src/advanced/service.ts"
.setBeforeGuardHooks({
  accountRead: async function (context, payload) {
    await requireReadableAccount(context, payload.accountId)
  },
})
.setCommandFunction(async function (context, payload) {
  const job = await context.queue.enqueue['banking.generateStatement'](
    { ...payload, initiatorPrincipalId },
    { tenantId: 'tenant-north' },
    { idempotencyKey: `statement:${context.message.principalId ?? 'unknown'}:${payload.accountId}` },
  )
  return { jobId: job.jobId, queueName: 'banking.generateStatement' }
})
```

The before guard is a business decision: it checks the principal’s current
right to read this account. The command then writes the verified principal into
the internal job payload; a caller cannot provide or replace it. The worker
checks that same business rule again before it reads account data. The
idempotency key makes repeat requests from the same principal for the same
account use the same logical queue key in the declared contract. It does not
provide a durable artifact policy.
