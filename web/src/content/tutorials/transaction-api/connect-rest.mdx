---
title: Expose commands through REST
description: Add HTTP metadata to the generated commands and call the same command boundary from the browser.
order: 24
---

The generated command builder owns its HTTP metadata. Add the routes after the
schemas and before the handler:

```ts title="recordTransactionCommandBuilder.ts"
.exposeAsHttpEndpoint('POST', 'transactions')
```

For the list command, use:

```ts title="listTransactionsCommandBuilder.ts"
.exposeAsHttpEndpoint('GET', 'accounts/:accountId/transactions')
```

Hono reads the path value into the command parameter schema and validates the
JSON body against the payload schema. It then invokes the registered PURISTA
command and returns its validated output. The browser must call this endpoint,
not the repository.

Add a short `fetch` function to the React screen and use it to list
`/api/v1/accounts/account-a/transactions`. The generated Hono configuration
also exposes OpenAPI at its configured API mount path; inspect it after you
start the project.

```bash title="Start the API and request the list endpoint"
npm run dev
curl -i http://127.0.0.1:3000/api/v1/accounts/account-a/transactions
```

This early endpoint is intentionally incomplete until the access chapter adds
authentication and business guards. Do not expose it to a network or treat it
as an account authorization example.
