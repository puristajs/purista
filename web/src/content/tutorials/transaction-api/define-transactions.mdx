title: Define the transaction contract
description: Replace the generated unknown schemas with a small checked transaction contract.
order: 22
---

Open generated `command/recordTransaction/schema.ts`. A schema is a checked
description of data. Replace its placeholder payload schema with the public
transaction shape:

```ts title="src/service/banking/v1/command/recordTransaction/schema.ts"
import { z } from 'zod'

export const recordTransactionInputPayloadSchema = z.object({
  accountId: z.enum(['account-a', 'account-c']),
  sourceTransactionId: z.string().min(1).max(80),
  bookedAt: z.string().datetime(),
  amountMinor: z.number().int().positive().max(Number.MAX_SAFE_INTEGER),
  currency: z.literal('EUR'),
  direction: z.enum(['debit', 'credit']),
})
```

Use the same transaction data for the output, plus a generated `transactionId`.
For `listTransactions`, make the parameter schema contain `accountId` and make
the output `{ accountId, transactions }`.

`amountMinor` stores EUR cents as a whole number: `4250` means EUR 42.50. This
avoids binary floating-point rounding at the public command boundary. The
example supports only EUR and two synthetic account IDs; it does not teach
currency conversion or settlement.

Add a schema test for a fractional amount and expect it to fail. Invalid input
must stop before any handler or repository operation.
