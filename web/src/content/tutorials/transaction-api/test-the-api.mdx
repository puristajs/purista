Keep two test levels. A command test calls the generated definition with a fake
repository. An HTTP test starts the local Hono composition and calls
`hono.app.fetch`. The final reference uses this second shape in
`examples/banking/src/banking.integration.test.ts`.

Test these cases before adding authentication:

| Case | Evidence |
| --- | --- |
| Valid synthetic EUR transaction | A record with a generated ID is returned. |
| Identical retry | The same logical record is returned. |
| Changed duplicate | `409` and no second record. |
| Fractional amount | `400` and the repository records nothing. |
| List request | It returns only the requested synthetic account's records. |

```bash title="Run the project tests"
npm test
```

The API works structurally, but it still needs an answer to “may this valid
person read or post to this account?” The next chapter adds server-trusted
identity and business guards; it does not treat a route as secure merely
because the browser hides a button.
