You have added transaction contracts, an injected repository, a record command,
and a history command to the project from chapter one. Hono exposes the
commands from their definitions; there are no parallel HTTP implementations
of their business logic.

Stop the development server and run:

```bash title="Check all implemented behavior"
npm test
npm run build
```

Expect six passing tests. The transaction tests use a real PURISTA bridge,
service, and Hono route. They prove these outcomes:

| Request or condition | Evidence |
| --- | --- |
| Valid POST | `200`, validated fields, and a generated transaction identifier. |
| History after POST | The same saved record appears in the account's history. |
| Duplicate source reference | `409`, with no second row. |
| Invalid amount | `400`, with no stored row. |
| Different known account | An empty array, not another account's records. |
| Unknown account identifier | `400` from parameter validation. |

The account filtering test proves data selection, **not** user authorization.
There is no trusted caller identity in this checkpoint.

## Check the listening application

Start `npm run dev` in one terminal. In another, from your project directory:

```bash title="Record and read through the real Node socket"
curl -i http://127.0.0.1:3000/api/v1/transactions \
  -H 'content-type: application/json' \
  --data-binary @fixtures/transaction.json
curl -i http://127.0.0.1:3000/api/v1/accounts/account-a/transactions
curl http://127.0.0.1:3000/api/openapi.json
```

The first two calls return `200`. The OpenAPI document lists the POST and
GET operations with their input and output schemas. Stop with Ctrl+C.
Starting again clears the repository; no Docker cleanup or database reset is
needed.

## Recover the completed source

From a clone of the PURISTA repository, this recreates the chapter in a new
directory using the CLI and the same documented edits:

```bash title="Replay the completed transaction chapter"

```
