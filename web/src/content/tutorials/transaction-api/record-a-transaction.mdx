---
title: Implement the record command
description: Turn the generated command placeholder into an idempotent in-memory transaction operation.
order: 23
---

The generated `recordTransactionCommandBuilder.ts` has a handler placeholder.
Add a small repository at `src/service/banking/v1/bankingRepository.ts` and
inject it from the composition root. The final reference implementation is
`examples/banking/src/repository.ts`.

Give the repository one business rule: the pair `accountId` and
`sourceTransactionId` identifies a logical imported transaction. An identical
retry returns the existing record. The same source ID with changed data returns
`409 Conflict`.

Replace the generated handler with a call to that resource:

```ts title="recordTransactionCommandBuilder.ts"
.setCommandFunction(async function (context, payload) {
  return context.resources.bankingRepository.record(payload)
})
```

Declare the resource on `bankingV1ServiceBuilder.ts`, then pass a new repository
when `bankingV1Service.getInstance(...)` runs in `src/index.ts`. A resource is
an explicit dependency supplied by the composition root. It keeps storage
ownership out of the command definition.

At this point, use a local development actor only while building. The next
chapter replaces that shortcut with server-owned identity and business guards.
