The service now has storage. Add a command that accepts a transaction and asks
that resource to save it.

Stop the development server and run:

```bash title="Generate recordTransaction"
npm run add:command -- record-transaction \
  --service banking --service-version 1 \
  --description "Record an already-posted synthetic transaction" --non-interactive
```

The generator creates `src/service/banking/v1/command/recordTransaction/`
and adds the definition to `bankingV1Service.ts`. Keep that generated
registration and `types.ts`; replace the following files.

## Connect the schemas

```ts title="src/service/banking/v1/command/recordTransaction/schema.ts"
import { z } from 'zod'
import { recordedTransactionSchema, transactionInputSchema } from '../../../../../transaction.js'

export const bankingV1RecordTransactionInputPayloadSchema = transactionInputSchema
export const bankingV1RecordTransactionInputParameterSchema = z.object({})
export const bankingV1RecordTransactionOutputPayloadSchema = recordedTransactionSchema
```

The payload is the POST body. It uses the transaction input schema we already
wrote. The route has no path parameters, and the output includes the saved
record's generated identifier.

## Implement the handler

```ts title="src/service/banking/v1/command/recordTransaction/recordTransactionCommandBuilder.ts"
import { bankingV1ServiceBuilder } from '../../bankingV1ServiceBuilder.js'
import {
	bankingV1RecordTransactionInputParameterSchema,
	bankingV1RecordTransactionInputPayloadSchema,
	bankingV1RecordTransactionOutputPayloadSchema,
} from './schema.js'

export const recordTransactionCommandBuilder = bankingV1ServiceBuilder
	.getCommandBuilder('recordTransaction', 'Record an already-posted synthetic transaction')
	.addPayloadSchema(bankingV1RecordTransactionInputPayloadSchema)
	.addParameterSchema(bankingV1RecordTransactionInputParameterSchema)
	.addOutputSchema(bankingV1RecordTransactionOutputPayloadSchema)
	.exposeAsHttpEndpoint('POST', 'transactions')
	.setCommandFunction(async function (context, payload) {
		return context.resources.transactions.record(payload)
	})
```

`context` provides the capabilities of this command, including the resource
declared on the service builder. `payload` is the validated input.
The handler returns the resource's result; PURISTA checks it against the output
schema before Hono returns it.

`exposeAsHttpEndpoint('POST', 'transactions')` makes Hono register
`POST /api/v1/transactions` at the next startup. There is no separate route
handler to write. We keep the default successful command status, HTTP `200`.

## Replace the generated placeholder test

```ts title="src/service/banking/v1/command/recordTransaction/recordTransactionCommandBuilder.test.ts"
import { expect, test } from 'vitest'
import { createTestBank } from '../../../../../testing/createTestBank.js'

const transaction = {
	accountId: 'account-a',
	sourceTransactionId: 'source-001',
	bookedAt: '2026-01-20T10:00:00.000Z',
	amountMinor: 1250,
	currency: 'EUR',
	direction: 'debit',
}

test('records a transaction and rejects duplicate and invalid requests', async () => {
	const bank = await createTestBank()
	const post = (body: unknown) =>
		bank.request('/api/v1/transactions', {
			method: 'POST',
			headers: { 'content-type': 'application/json' },
			body: JSON.stringify(body),
		})
	try {
		const recorded = await post(transaction)
		expect(recorded.status).toBe(200)
		expect(await recorded.json()).toEqual({
			...transaction,
			transactionId: expect.any(String),
		})

		const duplicate = await post(transaction)
		expect(duplicate.status).toBe(409)

		const invalid = await post({ ...transaction, sourceTransactionId: 'source-002', amountMinor: 12.5 })
		expect(invalid.status).toBe(400)
		expect(invalid.headers.get('content-type')).toContain('application/problem+json')
		expect(await invalid.json()).toMatchObject({ status: 400 })
	} finally {
		await bank.destroy()
	}
})
```

This test sends requests through Hono and the EventBridge to the real command.
It checks a saved record, a duplicate source reference, and an invalid
fractional-cent amount. Each test starts with fresh storage.

```bash title="Verify the completed record command"
npm test
npm run build
```

Expect five passing tests.

## Record a transaction yourself

Create a `fixtures` directory and `fixtures/transaction.json`:

```json title="fixtures/transaction.json"
{
	"accountId": "account-a",
	"sourceTransactionId": "source-001",
	"bookedAt": "2026-01-20T10:00:00.000Z",
	"amountMinor": 1250,
	"currency": "EUR",
	"direction": "debit"
}
```

Start `npm run dev` in terminal one. In terminal two, from the project
directory, run:

```bash title="Post the synthetic transaction"
curl -i http://127.0.0.1:3000/api/v1/transactions \
  -H 'content-type: application/json' \
  --data-binary @fixtures/transaction.json
```

The `@` tells curl to read the file. Expect `200` and the same fields plus
a `transactionId` containing a UUID. Sending the same file again returns
`409`; the repository does not store it twice.

The application still has no authentication. This is a local construction
step, not an endpoint for accepting transactions from customers.
Stop the server before [adding the history command](/tutorials/transaction-api/connect-rest/).
