title: Delete retained data
description: Delete the authorized preference through a normal protected PURISTA workflow.
order: 145
status: published
---

Deletion uses the same account-mandate guard as saving and reading. The
workflow calls `context.memory.principal().delete(...)` and returns a safe
`language: null` result. It cannot delete another person's data because the
principal scope is derived on the server.

The in-memory engine has no late queue writes in this checkpoint. A durable
production adapter needs its own deletion and retention proof before a
tutorial may promise deletion after restart.
