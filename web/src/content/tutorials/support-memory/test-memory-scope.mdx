Run each generated workflow test while you build it, then run the focused
integration proof from the repository root:

```bash title="Verify the support-memory boundary"
npm test -- --run src/service/bankingSupportMemory/v1/agent
npx vitest run examples/banking/src/memory/service.integration.test.ts
npm run test -w @purista/banking-tutorials
```

The focused memory test saves, reads, and deletes Alice's preference. It then
reuses one memory engine with Bob and proves that the copied conversation id
returns no value. It also proves Bob is denied before an Account C request can
enter memory. The main banking integration test repeats the scope check using
the opaque local-session path.

This proves in-process isolation and deletion. It does not prove persistence
across an application restart because the configured engine is intentionally
in memory.
