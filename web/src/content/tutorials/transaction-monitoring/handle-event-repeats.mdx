---
title: Make repeated delivery safe
description: Keep one review case when the same transaction event is delivered more than once.
order: 55
---

Events can be delivered more than once. Give the review-case repository a
unique key of transaction ID and rule version. A repeated event returns the
existing logical case; it does not create another case.

This protects the monitoring projection. It does not make the original
transaction write and event publication atomic. A failure in the consumer
cannot undo a transaction that the producer already recorded.

Test a duplicate event directly through the registered EventBridge and assert
that the projection still contains one case.
