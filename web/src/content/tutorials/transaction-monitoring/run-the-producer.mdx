---
title: Run the local transaction producer
description: Start the complete local application and record a synthetic transaction that the service can publish as a business fact.
order: 51
---

Start the example from the `purista` repository root:

```bash title="Start the Example Bank"
npm run dev -w @purista/banking-tutorials
```

Keep this terminal open. In a second terminal, create a Dana local fixture
session. Dana may record transactions for account A.

```bash title="Create Dana's local tutorial session"
curl --fail -c .tutorial-cookie -X POST http://127.0.0.1:3010/auth/login \
  -H 'content-type: application/json' \
  --data '{"actor":"dana"}'
```

```bash title="Record a high-value synthetic transaction"
curl --fail -X POST http://127.0.0.1:3010/api/v1/transactions \
  -H 'content-type: application/json' \
  -b .tutorial-cookie \
  --data '{"accountId":"account-a","sourceTransactionId":"monitor-demo-1","bookedAt":"2026-01-20T10:00:00.000Z","amountMinor":100000,"currency":"EUR","direction":"credit"}'
```

The command returns the recorded transaction. Its HTTP result does not include
the monitoring finding: a producer reports what happened, while a subscription
owns its separate projection. Sign in as Erin and call
`GET /api/v1/review-cases/account-a` to inspect the guarded review case, or use
the test page to prove the reaction.

If this request returns `403`, check that the local session is Dana's and the
account is `account-a`. A signed-in reader such as Bob still may not record a
transaction. A denied command does not reach its handler and therefore cannot
emit the event.
