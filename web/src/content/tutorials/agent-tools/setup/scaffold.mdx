Start in an empty parent directory. This chapter creates its own application,
so it has no hidden dependency on an earlier tutorial.

```bash title="Create and enter the agent-tools project" replay="parent"
npm create purista@latest support-agent-tools -- --runtime node --event-bridge default --non-interactive --defaults
cd support-agent-tools
```

Install the packages by their public npm names. The tutorial never copies
packages from the monorepo.

```bash title="Install PURISTA and Harness" replay="project"
npm install --save-exact @purista/core@4.0.0 @purista/harness@3.0.0 @purista/harness-openai@3.0.0 zod@4.4.3
npm install --save-dev --save-exact @purista/cli@4.0.0 typescript@7.0.2 vitest@4.1.10 tsx@4.23.12 @biomejs/biome@2.5.8
```

Make sure the generated project exposes the CLI scripts used below.

```json title="package.json" write
{
	"scripts": {
		"add:service": "purista add service",
		"add:command": "purista add command",
		"add:agent": "purista add agent",
		"build": "tsc --noEmit",
		"demo": "node --import tsx src/demo.ts",
		"lint": "biome check .",
		"start": "node --env-file-if-exists=.env --import tsx src/index.ts",
		"test": "vitest run"
	}
}
```

Create two narrow capability owners. `Support` owns support automation.
`Transaction` owns transaction records and the rules for reading them.

```bash title="Generate the services" replay="project"
npm run add:service -- support --description "Own support conversations and support automation" --non-interactive
npm run add:service -- transaction --description "Own transaction records and transaction business rules" --non-interactive
```

Generate the native agent and the two commands before editing their generated
files.

```bash title="Generate the agent and commands" replay="project"
npm run add:agent -- answer-transaction-question --service support --service-version 1 --description "Answer a support question with authorized transaction data" --non-interactive
npm run add:command -- get-transaction-summary --service transaction --service-version 1 --description "Read an authorized transaction summary" --non-interactive
npm run add:command -- answer-transaction-question --service support --service-version 1 --description "Answer a support question with authorized PURISTA tools" --non-interactive
```

The agent generator creates a native Harness module, a service-level Harness
composition, a mount policy, and the `.mountHarness(...)` registration on
`Support`. The command generators create command builders and register their
definitions on the correct services. We will replace the placeholder schemas
and handlers, while keeping that generated structure.

At the end of this page, these are the important roots:

```text title="Generated structure"
src/
├── harness/support/
│   ├── agent/answerTransactionQuestion/answerTransactionQuestionAgent.ts
│   └── supportHarness.ts
└── service/
    ├── support/v1/
    │   ├── command/answerTransactionQuestion/
    │   ├── harness/supportHarnessMount.ts
    │   └── supportV1Service.ts
    └── transaction/v1/
        ├── command/getTransactionSummary/
        └── transactionV1Service.ts
```

Run `npm run build` now. Generated placeholder code should compile before you
replace it.
