Script two strict model rounds. The first chooses `lookup_transaction`; the
second returns the final structured answer.

```ts title="src/agentTools.integration.test.ts"
provider.enqueueObject({
	object: {},
	toolCalls: [
		{
			id: 'lookup-1',
			name: 'lookup_transaction',
			arguments: { accountId: 'account-operating', transactionId: 'tx-100' },
		},
	],
	usage,
	finishReason: 'tool_calls',
})
provider.enqueueObject({
	object: { answer: 'Transaction tx-100 is pending for EUR 42.', transactionIds: ['tx-100'] },
	usage,
	finishReason: 'stop',
})
```

Start `Transaction` and `Support` on one `DefaultEventBridge`, then invoke the
Support command with trusted identity. Assert that the Transaction policy saw
that identity and that the declared custom event kept it too.

```ts title="src/agentTools.integration.test.ts"
expect(accountPolicy.canRead).toHaveBeenCalledWith({
	tenantId: 'tenant-example',
	principalId: 'principal-alex',
	accountId: 'account-operating',
})
expect(emitted).toEqual([{
	payload: { transactionId: 'tx-100', toolCallId: 'lookup-1' },
	tenantId: 'tenant-example',
	principalId: 'principal-alex',
}])
```

The denied test invokes `getTransactionSummary` with a policy that returns
`false` and asserts `transactionSummaryReader.getById` was never called. This
proves the guard prevents the protected resource effect instead of merely
changing the response afterward.
