An agent often needs information owned by another service. For example, a
support agent may need one transaction summary before it can answer a question.
The agent should not import the Transaction service or open its database. Its
tool calls the owning command through PURISTA EventBridge instead.

This chapter adds one read-only tool to the Example Bank support agent. The
banking story stays small so the framework boundary is easy to see:

```text title="Execution path"
Support command
  -> Support / 1 / answer_transaction_question agent (EventBridge)
  -> model chooses lookup_transaction
  -> typed PURISTA host-tool binding
  -> Transaction / 1 / getTransactionSummary command (EventBridge)
  -> account business guard
  -> injected transaction reader
```

The model supplies `accountId` and `transactionId` as untrusted tool input.
PURISTA carries `tenantId` and `principalId` from the original request across
both EventBridge calls. The Support and Transaction guards make separate
business authorization decisions before model or database work begins.

You only need Node.js 24 or newer and basic TypeScript knowledge. The required
path uses a fake model and an in-memory transaction reader, so it needs no API
key, database, HTTP server, or earlier tutorial. An optional final step swaps in
OpenAI without changing the Harness definition.
