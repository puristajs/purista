An agent often needs information that belongs to another service. The agent
must not import that service, open its database, or trust identity proposed by
the model. In PURISTA, the tool implementation invokes the owning service by
address through EventBridge. The command's business guards still decide
whether the caller may read the requested data.

This chapter adds one read-only tool to the Example Bank support agent. The
banking story stays small so the framework boundary is easy to see:

```text title="Execution path"
Support command
  -> Support / 1 / answer_transaction_question agent (EventBridge)
  -> model chooses lookup_transaction
  -> typed PURISTA host-tool binding
  -> Transaction / 1 / getTransactionSummary command (EventBridge)
  -> account business guard
  -> injected transaction reader
```

The model supplies `accountId` and `transactionId` as untrusted tool input.
PURISTA supplies `tenantId` and `principalId` from the original message. The
tool cannot replace those trusted values.

You will:

1. [generate the two services, the agent, and both commands](./setup/scaffold/);
2. [declare a portable native Harness tool and agent](./build/declare-host-tool/);

The retained source is in `examples/banking/chapters/agent-tools`. Its default

provider account or network request.
