An agent sometimes needs data owned by another service. In this chapter, a
Support agent asks for one transaction summary. The agent does not open the
Transaction database. Its tool calls the command that owns that data.

```text title="The request path"
Support / 1 / runAnswerTransactionQuestion command
  -> Support / 1 / answerTransactionQuestion agent
  -> model chooses lookupTransaction
  -> service-owned PURISTA host tool
  -> Transaction / 1 / getTransactionSummary command
  -> business guard and transaction reader
```

The command and agent have different addresses. The outer command is
`runAnswerTransactionQuestion`; the mounted agent is
`answerTransactionQuestion`. The host tool is defined with
`ServiceBuilder.defineTool(...)` under the owning Support service version.

The model supplies `accountId` and `transactionId` as untrusted input.
EventBridge carries the trusted tenant and principal. Support checks whether
the caller may use the agent, and Transaction checks whether the caller may
read the account.

The required path uses a strict fake model and needs no API key. It uses SQLite
for Harness storage. The live composition must use a file-backed SQLite store
when agent sessions must survive a process restart; `:memory:` is suitable only
for disposable demos and tests.
