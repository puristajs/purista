A model tool is an application capability, not a shortcut around the service
boundary. Apply four limits:

1. Bind only the narrow commands the agent needs. This chapter exposes a read
   command and no transaction mutation.
2. Keep business authorization on the owning command. Other callers receive the
   same rule.
3. Pass `context.idempotencyKey` to every side-effecting command, queue job, or
   external provider. Harness derives it from the logical tool call and keeps it
   stable across approval resume and durable recovery.
4. Treat custom events as at-least-once facts. Include a stable call or
   idempotency id and make subscribers deduplicate effects.

The parameter schema makes the retry requirement visible in the command
contract.

```ts title="src/service/transaction/v1/schema.ts"
export const getTransactionSummaryParameterSchema = z.strictObject({
	idempotencyKey: z.string().regex(/^tool_[a-f0-9]{64}$/),
})
```

This lookup is read-only, so the key mainly proves propagation. A future
mutation command must enforce the key in its repository or downstream provider;
the Harness cannot turn an arbitrary external side effect into exactly-once
execution.

Use tool approval for a sensitive operation that a human must review. The next
review chapter will keep that approval as a structured interrupted result for
the UI rather than converting it into HTTP 500.
