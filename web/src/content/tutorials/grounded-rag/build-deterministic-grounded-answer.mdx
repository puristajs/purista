The answer command does not ask a model to fill in missing information. It
uses the selected chunks directly. This makes the chapter easy to test: a
reply can only contain text that the repository found for the permitted
collection.

```ts title="examples/banking/src/knowledge/answer.ts"
const sources = repository.search(input.collectionId, input.question).slice(0, 2)

if (sources.length === 0) {
  return {
    answer: 'I could not find an authorized document passage for that question. Ingest an account guide first, then ask again.',
    sources: [],
  }
}

return {
  answer: `Grounded answer: ${sources.map(source => source.excerpt).join(' ')}`,
  sources: sources.map(({ documentId, title, revision, chunkId, excerpt }) => ({
    documentId, title, revision, chunkId, excerpt,
  })),
}
```

The generated `answerKnowledgeQuestion` command exposes the same result at
`POST /api/v1/knowledge/answers`. It has a before guard for collection scope,
then calls this helper. The helper repeats the check because the AI SDK route
also uses it. Keeping one server-owned function prevents the two transports
from choosing different retrieval rules.

This answer is a teaching implementation. It does not summarize, explain,
resolve conflicting documents, or guarantee that a matching chunk fully
answers a question. A model-backed answer belongs in a later guarded chapter;
that model must receive only the already-authorized excerpts.
