The `add:queue` command created the queue worker and its generated test. Open
the worker builder and use the typed queue payload. For this teaching example,
the worker counts transaction and monitoring projections and stores metadata.
It does not claim to calculate a settlement difference.

```ts title="reconcileWorker queue-worker builder"
.setHandler(async context => {
  const payload = context.message.payload as { day: string; source: 'banking-projections' }
  const transactionCount = ['account-a', 'account-c'].flatMap(id =>
    context.resources.bankingRepository.list(id),
  ).length
  const run = context.resources.operationsStore.recordReconciliation({
    runId: `reconciliation-${payload.day}`, day: payload.day, transactionCount,
    findingCount: context.resources.operationsStore.listFindings().length,
    completedAt: new Date().toISOString(),
  })
  await context.job.complete(run)
  return { status: 'success' as const }
})
```

The worker receives a server-created job, not browser data. Keep its work
small, deterministic, and visible in the stored projection.

```bash title="Run the worker test"
npm test -- --run src/service/bankingOperations/v1/queue-worker/reconcileWorker
```
