---
title: Define the source-scoped contract
description: Make the occurrence and business-owned reconciliation source explicit in command, event, and queue data.
order: 82
---

The day alone is not enough. A reconciliation run is for a particular source;
without that source, neither a guard nor an idempotency key can state what it
protects.

```ts title="advanced/contracts.ts"
export const reconciliationDueEventSchema = z.object({
  day: z.string().regex(/^\d{4}-\d{2}-\d{2}$/),
  source: z.literal('banking-projections'),
})
```

Generate the queue and first worker from the project root:

```bash title="Generate the reconciliation queue and worker"
npm run add:queue -- reconcile-banking-projections \
  --service banking-operations --service-version 1 \
  --worker-name reconcile-worker --worker-mode continuous \
  --description "Reconcile one local banking projection"
```

Use the same schema for the generated command payload, the event payload, and
the queue payload. That stops the scheduler and manual request from drifting
into separate representations.

The example's `canRunReconciliation` check is deliberately separate from
account-read and review-case permissions. Dana is assigned to the named
operations source for `tenant-north`; a normal account reader is not.
