---
title: Store one run per day
description: Use the occurrence day as the local projection key so repeated worker calls return one logical run.
order: 84
---

The projection store treats a day as the identity of a reconciliation run:

```ts title="examples/banking/src/advanced/repository.ts"
recordReconciliation(run: ReconciliationRun) {
  const existing = this.reconciliationRuns.find(entry => entry.day === run.day)
  if (existing) return existing
  this.reconciliationRuns.push(run)
  return run
}
```

The service also uses the same day in its queue idempotency keys. The command
uses `reconciliation:${payload.day}`, and the event-to-queue binding maps an
event to `reconciliation:${String(event.day)}`. These shapes communicate the
intent that one day has one logical run.

This is not a durable uniqueness guarantee. The store and queue are both lost
when the process stops, and the source does not model partial work, a retryable
upstream error, or an occurrence revision. A durable implementation needs an
atomic occurrence claim and tests that restart the relevant processes.
