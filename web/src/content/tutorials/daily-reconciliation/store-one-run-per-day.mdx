---
title: Make one run per source and day
description: Use the business occurrence as the queue idempotency key and keep the projection repeat-safe.
order: 84
---

Schedules and queues may deliver again. The business occurrence is the pair of
`source` and `day`, so use it for the generated command's enqueue key:

```ts title="runReconciliation command"
const job = await context.queue.enqueue['banking.runReconciliation'](
  payload,
  { tenantId: 'tenant-north' },
  { idempotencyKey: `reconciliation:${payload.source}:${payload.day}` },
)
```

Use the same key in the event-to-queue binding:

```ts title="Service composition"
.bindEventToQueue(BankingTutorialEvent.reconciliationDue, 'banking.runReconciliation', {
  idempotencyMode: 'advisory',
  idempotencyKey: event => `reconciliation:${String(event.source)}:${String(event.day)}`,
})
```

The local projection also records `reconciliation-${day}` deterministically.
In production, make that a unique database constraint including the source.
Idempotency configuration is useful protection, not a substitute for durable
storage or a tested recovery policy.
