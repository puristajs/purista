## Prerequisites

Use Node.js 24.15 or newer, or a supported Bun runtime, and a TypeScript runner.
This example uses the OpenAI adapter only to make the first live call concrete;
the Harness API remains the same when you replace it with another provider
adapter. Do not install adapters for providers your application does not use.

## Install

Install the core runtime and only the provider adapter your application uses:

```sh
npm install @purista/harness @purista/harness-openai zod
npm install --save-dev tsx typescript
```

`zod` is an explicit application dependency: it owns the schemas at your input,
tool, and output boundaries. The Harness deliberately does not re-export it.

### Optional: install the AI Harness skill

If an AI coding assistant will help maintain this application, install the
recommended `ai-harness` skill once. It gives the assistant the same typed
runtime, provider-neutrality, privacy, testing, and telemetry boundaries used
throughout this handbook. It is documentation for the assistant, not a
runtime dependency and not part of your deployed application.

```sh
npx skills add puristajs/harness --skill ai-harness
npx skills list
```

For an agent-specific installation, add its selector, for example
`--agent codex`. New PURISTA projects already include the framework skill;
install this additional skill when the project also owns a Harness runtime.

Create a local `.env` that is ignored by version control:

```dotenv
OPENAI_API_KEY=replace-with-a-development-secret
OPENAI_MODEL=gpt-5-mini
```

Set `OPENAI_API_KEY` and optionally `OPENAI_MODEL` through your deployment
secret store in production. Do not put credentials in source, skills, fixtures,
or logs.

## Define one model and one agent

```ts
import { z } from 'zod'
import { defineHarness, JsonLogger, inMemorySandbox } from '@purista/harness'
import { openai } from '@purista/harness-openai'

const harness = defineHarness({ name: 'support' })
  .logger(new JsonLogger({ level: 'info' }))
  .telemetry({ contentCaptureMode: 'NO_CONTENT' })
  .sandbox(inMemorySandbox())
  .models({
    assistant: {
      provider: openai({ apiKey: process.env.OPENAI_API_KEY! }),
      model: process.env.OPENAI_MODEL ?? 'gpt-5-mini',
      capabilities: ['object']
    }
  })
  .agents(({ agent }) => ({
    support: agent({
      model: 'assistant',
      input: z.object({ question: z.string().min(1) }),
      output: z.object({ answer: z.string() }),
      builtinTools: false,
      instructions: 'Answer clearly. Return the requested object only.'
    })
  }))
  .build()
```

The model alias (`assistant`) is the provider-neutral contract used everywhere
else. Its `capabilities` are intentionally narrow: this agent requests a
validated object and cannot use tools yet. Zod validates the external input
before the model loop and the returned output before the application receives
it.

## Invoke through a session

```ts
const session = await harness.getSession('tenant-a:customer-42')

try {
  const result = await session.agents.support.prompt({
    question: 'How do I change my delivery address?'
  })
  console.log(result.answer)
} finally {
  await session.release()
  await harness.shutdown()
}
```

Run the example with the TypeScript runner you chose. For example, if the code
is in `src/support.ts`, add this script to `package.json`:

```json
{
  "scripts": {
    "support:example": "tsx --env-file=.env src/support.ts"
  }
}
```

```sh
npm run support:example
```

The output is a validated `{ answer: string }`, not a provider response. If the
provider is unavailable, credentials are invalid, or the returned value cannot
match the schema, the call rejects with a normalized Harness error. Map that
error to your HTTP, queue, or UI protocol in application code; do not expose a
raw provider response to callers.

The session scopes history, state, and live resources. `release()` ends live
resources while retaining durable history; `close()` is destructive and deletes
the session record. Use a stable, privacy-safe application session key and let
your transport decide whether same-session requests serialize or receive a
busy response.
